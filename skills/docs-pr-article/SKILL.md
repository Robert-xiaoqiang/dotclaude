# Skill: docs-pr-article

## Purpose
一篇论文的中文宣传稿不是摘要的翻译，也不是论文的缩写。它的读者在手机上滑过，三秒内决定要不要读完，而他关心的是这件事新在哪、数字有多大、跟他有什么关系。这份 skill 记的是 量子位 / 机器之心 这类账号真正在用的标题公式、开头写法、小节骨架、图的位置，以及把结果卖出去而不编造结果的边界。文字规则走 `writing-style-zh`，起草走 `writing-chatgpt`，这份只管宣传稿特有的结构与销售。

## When to Use
- 给一篇论文、模型或开源发布写中文宣传稿：公众号推文、小红书笔记、中文推特线程，或给合作者改的初稿。
- 一份稿子开头在谈 AGI 是圣杯、谈想象一下未来，需要换掉。
- 一份稿子读起来像摘要的翻译，需要换成宣传稿的骨架。
- 要决定一个结果可以卖到多硬。
- 不管英文宣传稿，也不管论文正文（`writing-paper`）、实验节（`writing-analysis`）、幻灯片（`docs-slides`）。

## 平台不是一个，两家的规则相反

这是本 skill 唯一一条靠搜索纠正了直觉的发现，写在最前面，因为它会让人把稿子投错地方。

| | 公众号（量子位 / 机器之心 / 新智元） | 小红书 |
|---|---|---|
| 标题长度 | 不限，实测常 25 到 40 字，带副标题 | 20 字以内 |
| 感叹号与钩子 | 鼓励，`！` 几乎是标配 | 克制 |
| 夸张标题 | 是风格的一部分 | **会压推流**，夸大、诱导式标题在小红书不受欢迎，反复用会限流 |
| 正文长度 | 长，实测一篇约 59 段 | 每段不超过 3 行，短句短段 |
| emoji | 基本不用 | 每段 1 到 2 个，列表项各配一个 |
| 结构 | 小标题分节 | 封面 + 分点 + 5 到 10 个标签 |
| 署名 | `量子位 \| 公众号 QbitAI`、投稿标注 | 个人口吻 |

**所以「卖得更硬」这件事只对公众号成立。** 同一份内容投小红书要反向改：标题收敛、正文切碎、加 emoji 和标签，而不是把公众号稿贴过去。一份稿子服务两个平台时，写两版，不要写一版折中的。

## 标题：六个真实公式

从 量子位 与 机器之心 的真实标题里归纳。**共同点是：标题里必须有一个具体的数、一个机构、或一个会议期刊名，三者至少占两样。**

| 公式 | 实例 |
|---|---|
| 数字打头 + `！` + 机构 + 成果 | `495篇参考文献！北交大清华等高校发布多语言大模型综述` |
| 动词短语 + 幅度 + `！` + 机构 `提出` + 方案 `：` + 第二个指标 | `让大模型"瘦身"90%！清华&哈工大提出极限压缩方案：1bit量化，能力同时保留83%` |
| 口语化机制 + 指标 `狂飙` 数字 + `丨` 机构 | `纯靠"脑补"图像，大模型推理准确率狂飙80%丨剑桥谷歌新研究` |
| `首个` + 成果 + `问世！` + 能力 + `还有…开源` | `首个个性化对齐大模型问世！可精准识别用户内在动机和偏好，还有百万用户画像开源数据集` |
| 机构系 + `登` 期刊 + `！` + 具体数字能力 + `代码已开源` | `清华系细胞大模型登Nature子刊！能对人类2万基因同时建模，代码已开源` |
| `优于` 对标工作 + `，` + 机构 `提出` + 方法名 | `优于Mask R-CNN，港中文&腾讯优图提出PANet实例分割框架` |

可复用的构件，按出现频率：`提出`、`首个`、`登 X 刊`、`入选 X 会`、`代码已开源`、`丨`、`&` 连接两个机构、`「」` 包住关键词、一个百分比或倍数。

**疑问句标题是公众号允许的例外。** `如何让大模型感知知识图谱知识？蚂蚁联合实验室：利用多词元并行预测给它"上课"`、`「羊驼」们走到哪一步了？研究表明：最好的能达到GPT-4性能的68%` —— 两条都是问号后面立刻给答案，所以读者没有悬着。`writing-style-zh` 第 8 条禁疑问句标题，那条管的是报告与论文的小标题；宣传稿的主标题按这里。**但小节标题仍然不用疑问句。**

## 开头两句，不是开头两段

这是宣传稿最常写坏的地方，也是作者点名要改的地方。

量子位实测的开头是两句，一共 36 个字：

> 对大模型进行量化、剪枝等压缩操作，是部署时最常见不过的一环了。
> 不过，这个极限究竟有多大？

**形状是：一句读者已经同意的常识，一句把常识推到边界上的问题。** 然后 `一起来看看。`，然后封面图。全文没有一句话谈行业愿景。

被作者点名否掉的反面（OSCAR 稿，见 `references/oscar-wechat-zh.txt` 第 3 行起）是三段 400 余字，依次谈 AGI 是圣杯、谈人类水平智能的终极目标、谈想象一下说句话电脑就自动操作、谈 Anthropic 与 OpenAI 的产品，到第三段才说出本文要讲的工作。作者的评价是「too verbose, we need to insight」。

**开头的预算：两到三句，100 字以内，第二句之前必须出现本文要讲的那个东西或那个矛盾。** 行业背景、竞品回顾、愿景描写一律删掉，需要对标竞品就放进后面的对比里。

可用的三种开头：

| 类型 | 形状 |
|---|---|
| 常识加边界 | 一句公认做法，一句「那它的极限在哪」 |
| 反直觉数字 | 直接把最反常的那个数摆出来，再说它是怎么来的 |
| 一句矛盾 | 两个都成立但凑在一起矛盾的事实并置 |

## 骨架

公众号稿的节序，与 OSCAR 稿和量子位稿共同的部分：

```
标题
一句话导语（可选，10 到 20 字，钩子的延伸）
署名行
开头两到三句 + "一起来看看。"
封面图 / 论文信息图（标题、机构、arXiv 链接）
## 问题：现有做法在哪卡住
## 方法：这篇怎么做的（编号 1 2 3 4，每条一个机制，图跟在条目后）
## 结果：数字（图表截图 + 正文把关键数复述一次）
## 结语 / 一句话总结
论文地址、代码地址
— 完 —
```

**与论文的节序不同的三处，都是刻意的。** 论文的 Introduction 要铺literature，宣传稿第一节直接说卡在哪，不列文献。论文的 Methods 在后面，宣传稿把方法放第二节，因为读者是为了看新机制来的。论文有 Discussion，宣传稿的结语只有一两句。

**方法节用编号条目，不用散文。** 这是宣传稿与论文正文最大的形状差异：OSCAR 稿的方法节是 4 条编号，量子位稿是 2 条编号加小标题。一条一个机制，一条两到四句，图紧跟在条目后面。`writing-style-zh` 禁的是报告里反射式的三连排比，不禁宣传稿方法节的编号列表，因为那是读者在手机上扫的唯一入口。

## 小标题写成断言

OSCAR 稿的小标题用 `主题 —— 副题` 的形状：

```
## 操作系统UI交互自动化面临的挑战 —— 动态自适应难题
## OSCAR 的独特设计 —— 灵活状态机与动态重规划的巧妙结合
## OSCAR 实验验证 —— UI 理解、定位和动态导航能力的实力认证
```

量子位的更短，而且**结果节的小标题本身就是结论**：`模型越大，效果越好`。这是更好的写法，读者扫小标题就拿到了全文的结论链。

**所以：小节标题是一句断言，或一个点明对象的名词短语，不是「实验验证」这种栏目名。** `—— 副题` 的形状可以用，但副题要带信息，不能是「的实力认证」这类自我表扬。`实力认证`、`巧妙结合`、`开启新时代` 都是空话，按 `writing-style-zh` 的少用词处理。

## 图的位置与图注

| 位置 | 内容 |
|---|---|
| 开头两句之后 | 封面图，或论文信息图（论文标题、机构、arXiv 链接） |
| 每个方法条目之后 | 该机制的示意图 |
| 结果节 | 表格与曲线的截图，一张一个结论 |

图注是名词短语加编号，`图 3 OSCAR状态机`、`图 1. 论文信息（https://arxiv.org/abs/...）`。量子位用 `△` 作图注前缀。**论文信息图是公众号的惯例，一张图里放论文标题、作者机构和 arXiv 链接，等于把 credential 一次性交给读者。**

正文不把图里的字再说一遍（`writing-style-zh` 第 11 条），但结果节例外：**关键数字要在正文里出现一次**，因为图是截图，读者在手机上可能不点开。

## 卖点：能夸到哪，从哪一步起算编

作者的原话是「even overclaim it」。宣传稿确实比论文松，但松的是语气强度，不是事实集合。

**可以做的：**
- 挑最大的那个数当标题，不必在标题里给出它的对照。
- 用 `首个`、`最强`、`狂飙`、`瘦身 90%` 这类强度词修饰一个真实的数。
- 把论文里一句谨慎的结论说成一句肯定句。
- 不在标题和开头提局限，局限放结语或正文一句。
- 选最有利的对照组当主对照。

**不可以做的，因为这些是编：**
- 造一个论文里没有的数，或把一个数的条件改掉（把某个子集上的结果说成全集上的）。
- 把没跑的实验说成跑了。
- 声称一个论文明确不声称的东西。**量子类工作尤其危险**：论文写着不声称量子优势，稿子里暗示量子加速，会被领域内直接拆掉，而拆的人就是审稿人。
- 隐瞒一个与标题直接冲突的负结果。标题说 scaling 有效、正文不提某个规模上反而更差，是宣传稿最容易被挂的一种。

**判断方法：这句话如果被论文作者的竞争对手逐句核对，哪一句会让作者需要解释？** 需要解释的就是越界。强度词不需要解释，改过条件的数需要解释。

## 交付：docx 与可预览的 PDF

公众号的工作流是把稿子贴进编辑器，所以交付物是 `.docx`，再转一份 `.pdf` 便于远程预览。

```sh
pip install python-docx
# 中文字体：没有 CJK 字体时 soffice 导出的 PDF 全是豆腐块
curl -sSL -o ~/.fonts/NotoSansSC-Regular.otf \
  https://github.com/notofonts/noto-cjk/raw/main/Sans/SubsetOTF/SC/NotoSansSC-Regular.otf
fc-cache -f && fc-list :lang=zh family      # 必须看到 Noto Sans SC
soffice --headless --convert-to pdf --outdir PR PR/article.docx
```

**soffice 可能根本读不进 docx。** 一台只装了 LibreOffice Draw/Impress 的机器上
`share/registry/` 里没有 `writer.xcd`，任何 `.docx` 都会以 `Error: source file could not be
loaded` 失败，连一个只有一行字的 docx 也一样。先用一个一行字的 docx 试一次，确认这条路通，
再去调版式。不通就走 xelatex：

```sh
# 可靠的那条路，不依赖 LibreOffice
xelatex article.tex    # \usepackage{xeCJK} + \setCJKmainfont{Noto Sans SC}
```

**检查 PDF 里的中文真的渲染了，不要只看文件生成成功。** 没有 CJK 字体时 soffice 照样退出 0，
PDF 照样有页数，中文全是方框。两个可靠的核对：xelatex 的 log 里 `Missing character` 必须是
0 次；把 PDF 的 ToUnicode CMap 解压出来，数一下落在 U+4E00 到 U+9FFF 的码点，能读出中文就是真渲染了。
数 `/BaseFont` 不可靠，对象流是压缩的，正则看不见。

docx 的排版：正文 11pt，`Noto Sans SC`，段距 6pt，标题加粗不加下划线，图位置留一行 `【图 N：说明】` 占位，由人工在公众号编辑器里替换成真图。

## Rules
1. **开头两到三句，100 字以内，第二句之前出现本文的对象或矛盾。** 行业愿景、AGI、想象一下、竞品回顾全部删掉。
2. **标题里有数、有机构、有会议期刊名，至少占两样**，且那个数必须是论文里真有的。
3. **小节标题是断言或点名对象的名词短语**，结果节的标题直接写结论。栏目名式标题（`实验验证`）与自我表扬式副题（`实力认证`）都换掉。
4. **方法节用编号条目，一条一个机制，图紧跟其后。**
5. **结果节的关键数字在正文里出现一次**，不要只留在截图里。
6. **强度词可以夸，事实集合不能动。** 改条件的数、没跑的实验、论文明确不声称的结论，三条是红线。
7. **与标题直接冲突的负结果必须在正文出现一次**，否则稿子是可被挂的。
8. **公众号稿与小红书稿写两版**，不写一版折中的。小红书的夸张标题会压推流。
9. **文字规则走 `writing-style-zh`**，起草交给 `writing-chatgpt` 的 writer，判断看这里。
10. **PDF 产出后确认中文渲染**，字体缺失时 soffice 不报错。

## Anti-patterns
- **AGI 圣杯开场。** 四百字之后读者还不知道这篇讲什么。作者对 OSCAR 稿的评价就是这一条。
- **摘要直译。** 把论文摘要逐句译成中文当正文，于是方法节是散文、没有编号、没有图，读者在手机上无处落眼。
- **栏目名小标题。** `背景介绍`、`方法概述`、`实验验证`、`总结展望` 四个标题扫完，等于什么都没读到。
- **一版稿投两个平台。** 公众号的 40 字标题带两个感叹号贴到小红书，限流。
- **把局限藏干净。** 标题卖 scaling，正文不提最小规模上反而更差，被同行发现一次就不只是这篇的信誉问题。
- **豆腐块 PDF。** 交一份中文全是方框的 PDF，因为只检查了 soffice 的退出码。
- **图注写成句子。** `图 5 展示了我们的方法如何通过状态机实现动态重规划` 应为 `图 5 任务分解与重规划`。

## Companions
`writing-style-zh`（中文交付物的用词与句式，这份稿的文字规则全在那里）· `writing-chatgpt`（writer 工具，起草交给它）· `writing-paper` 与 `writing-analysis`（论文正文与实验节，和宣传稿的骨架刻意不同）· `docs-slides`（讲稿）· `drawing-figure`（配图）· `conventions`（技能族索引）
