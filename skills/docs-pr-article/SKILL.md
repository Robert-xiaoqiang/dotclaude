# Skill: docs-pr-article

## Purpose
一篇论文的中文宣传稿是给手机上滑过的读者写的，他三秒内决定读不读。这份 skill 管宣传稿特有的四件事：版式（机器之心 AIxiv 已发表稿件的前置结构），标题（交给 writer 生成，多版本交付），正文节奏（用真实语料量出来的目标值），以及从论文里裁图、构建 .docx 和 .pdf。文字规则走 `writing-style-zh`，起草走 `writing-chatgpt`。

**这份 skill 里的每个目标值都来自 `scripts/corpus_stats.py` 对真实稿件的统计。** 第一版 skill 凭一篇参考稿和几条搜索结果写成，结果正文段落中位数写到 152 字，而量子位是 47 字；数字密度是语料的八倍。凭印象写的宣传稿规则，量一次就会被推翻。

## When to Use
- 给一篇论文写中文公众号稿、机器之心 AIxiv 投稿稿、小红书笔记，或给合作者改的初稿。
- 一份稿子开头在谈 AGI、谈想象一下未来、回顾竞品产品。
- 一份稿子读起来像摘要的翻译，或者像一张表被念出来。
- 要决定一个结果可以卖到多硬。
- 不管论文正文（`writing-paper`）、实验节（`writing-analysis`）、幻灯片（`docs-slides`）。

## 交付物与目录

**同步出去的只有 `.docx` 和 `.pdf`。** `.docx` 贴进公众号编辑器，`.pdf` 用来远程预览。稿件源文件、裁出来的图、拼装脚本都不是交付物，不进远端。

```
PR/                      远端只同步这里的 *.docx 和 *.pdf
pr-building/             本地，gitignore
  crops.json             要裁哪些图，从哪个 PDF，按哪个图注
  assets/*.png           裁出来的图
  heads.json             每个版本的标题、副标题、开头
  intro.txt              作者简介
  body.txt               各版本共用的正文
  assemble.py            拼出 src_v*.txt
  build.sh               一条命令重建全部交付物
```

`.gitignore` 的写法是先忽略 `PR/*`，再放行 `!PR/*.docx` 与 `!PR/*.pdf`，然后忽略 `pr-building/`。项目里如果已经有全局的 `*.pdf` 忽略规则，放行那一行要写在它后面。改完用 `git check-ignore -v` 逐个确认，**论文本身编译出的 PDF 必须仍然被忽略**。

## 前置结构：照已发表的 AIxiv 稿件

机器之心 AIxiv 专栏是作者投稿、平台发布的格式，量子位、新智元的作者投稿稿件也接近它。已发表的一篇（2025-02-03，作者本人的 OSCAR 稿）的前置部分依次是：

```
标题                    解放双手！OSCAR让操作系统交互实现自然语言「自由」
导语 / 副标题           破解操作系统智能交互难题。
[平台的专栏横幅与说明]   由机器之心加，作者不写
**作者简介，整段加粗**   **本文作者王晓强，……博士生，师从刘邦教授。……**
开头段落
[论文截图]
- 论文题目：OSCAR: Operating System Control via State-Aware Reasoning and Re-Planning
- 论文链接：https://arxiv.org/abs/2410.18963
## 正文第一节
```

照这个顺序构建，有三处容易做错：
- **作者简介整段加粗**，不是灰底小字框。
- **论文信息是列表**，作者用的词是「论文题目」，不是「论文标题」。
- **副标题**在标题下单起一行，作者要求写成 `——` 打头，形状是「动词 + 一个被攻克的难题」，八到十四个字：`——破解操作系统智能交互难题`。写成复述机制的句子（`——解决全序列共用固定电路的限制`）就废了。

**论文截图**是第一页从标题到最后一行作者、单位、邮箱，停在 Abstract 之上，不含摘要。`crop_paper.py header` 自动定位。

**先确认论文是否已经在 arXiv 上，方法是打开 `arxiv.org/abs/<编号>` 或直接问作者，不要只查 `export.arxiv.org` 的检索接口。** 一次真实的失误：接口按标题、按作者、甚至按确切编号都查不到，于是稿子里写成了「即将发布」，而论文三周前就已上线。宣传稿通常在 arXiv 之后发，所以默认它已经在了，查不到就问。

**`论文题目` 照 arXiv 列表页上的标题写，大小写也照抄**（列表页可能是 Title Case，而 PDF 首页不是）。链接只写在论文信息块里，开头不再单写一句「论文已发布在 arXiv」，作者把这句删了。真的还没上线时才写「arXiv 预印本即将发布」，绝不编号。

## 标题：writer 生成，多版本交付

**标题交给 writer 生成，agent 不自己写。** 作者的原话是「问问 chatgpt 可以么？自己写的是你妈？」。agent 的事是给 writer 事实清单、真实标题语料和作者点名的角度，再把它的输出拿回来审。

**交付几个完整版本，不在一篇文章里留候选。** 作者的原话是「不要给我留候选，候选的话你可同时生成几个版本，不要一个」。做法：
1. writer 先出约二十个「标题 + 副标题」，分布在作者点名的角度上：「当 X 遇上 Y」、拟人化的被动问句（「被量子纠缠了？」）、「X 进入 Y 时代？」、量子位的硬数字公式（数字 + ！+ 机构 + 提出）、「首个」。
2. writer 从中挑三个**不同角度**的，各配一个跟着钩子走的开头。
3. 三个版本共用正文，各自是一份完整的 `.docx` 和 `.pdf`。

**作者选定标题以后只交一个版本，文件名不带版本号。** 作者看到三版之后的原话是「remove those legacy version, remove the trailing vxxx」。构建前清掉上一轮的 `src_v*.txt`，否则从 `heads.json` 删掉的版本会从旧源文件里复活（真实发生过，表现为 `KeyError: 'v2'`）。**作者口述的标题照用，只统一空格**（中文词之间不留空格，中文与英文、数字之间留一个），不改字。

**小节标题用讲稿的名词短语，不用结论句。** 照 `docs-slides` 研究报告一类的标题写法：点出这一节讲的对象和它的哪一面，`量子比特、电路与读出`、`HyperQ 的整体结构`、`电路超网络`、`实验结果`。不写陈述句、结论句、冒号加副题、疑问、数字、比喻。这一条推翻了早先「结果节标题写成结论」的建议（那是量子位的写法）：作者认为结论式、口号式的小标题是 AI 腔。主标题仍然可以标题党。

**一节讲一组图，按图的顺序讲。** 作者给的分节是：入门（自画示意图）、整体结构（流程图）、电路超网络（超网络面板与梯度方差）、实验结果（主表、搜索对比、真机）。每节先放图，再顺着图从左到右讲，不讲图里没有的东西。

审 writer 的标题时查这几条，每条都在真实一轮里发生过：
- **长度。** 108 个真实标题的中位数 34 字，四分位 29 到 38，超过 40 字在手机上折三行。同一批标题里带 ！ 的 41%、带 ？ 的 11%、带数字的 52%，「首个/首次」21%，「进入…时代」9%，「当 X 遇上 Y」只有 2%：后两种显眼，但少有先例。机构标签会把标题撑长，两个机构名连写的标签曾把一个标题推到 53 字，缩成一个机构名才回到 36。
- **数、机构、会议期刊名至少占两样**，问句钩子后面补一个机构标签就够。
- **「超过 X」必须带条件。** 只有最宽的配置超过了对照，标题和开头就必须写出是哪个配置，否则最窄配置的读者会发现它连基线都不如。
- **歧义词。** 量子论文的「N 比特」没有上下文会被读成 N 位计算机，标题里写「N 量子比特」。
- **标题丢了领域。** writer 收紧一个标题时删掉了「量子电路」「扩散大模型」，只剩数字钩子，刷到的人不知道这篇讲什么。
- **选出的三个里有一个读者看不懂的。** 以一个技术量（某种方差恒为某个值）为钩子的标题不是标题党，读者不知道那个量是什么，要换成作者点名的角度。

## 开头

开头两到三句，约 100 字，跟着该版本标题的钩子走：第一句是读者已经同意的常识或一个反差，第二句把它推到边界。**标题和开头都没出现方法名时，开头补一句点名团队与方法，方法名加粗。**

**跨领域论文的开头另有一个形状。** 读者是计算机研究员，懂大模型，不懂另一个领域（量子、生物、物理）。作者定下的顺序是：
1. 先用一条近期新闻说 AI 正在改变那个领域（量子论文用的是 OpenAI 的 GPT-5.6 Sol 在 MIT 超导芯片上做校准实验）。
2. 再反过来问那个领域能不能增强 AI，用一两句理论线索撑住这个问句（量子互文性，量子优越性之争）。**引用一场争论就写出对方说了什么**：只写「IBM 随后质疑了这一估计」，作者的第一反应是「IBM 怎么质疑的呢？」，要写成 IBM 认为用 Summit 约 2.5 天。
3. 再说本文是一次正式尝试，方法名加粗；用结果收住，**结果句先写最强的那个数，限定条件放在后面**。不写「首个」「全球首次」，除非有出处。
4. 不写「论文已发布在 arXiv」，链接在论文信息块里。

三到四个短段，合计 250 字以内。新闻与背景都先查出处（谁、何时、做了什么、局限，例如那次实验在弱信号时仍要人帮），只作背景，不写成本文的成果。**作者口述的卖点照用，但把会被挑错的那部分改成真的说法**：「让大模型运行在超导量子计算机上」改成「让大模型在推理时调用真实的超导量子计算机」，因为模型主体跑在 GPU 上，只有电路在真机执行，而且只在配对子集上。「从 16 到 64 量子比特都超过经典基线」改成「性能随量子比特增加持续上升，64 量子比特时超过经典基线」，因为 16 量子比特时还低于基线。

**正文第一节是一个只讲三个概念的入门小节，配一张自己画的示意图，不用论文里的图。** 作者看到论文图的面板后说「直接用论文里的不合适」：论文图是给同行看的，默认读者认识 IQP、Hadamard 层与读出旋转。入门图只画概念，一个概念一个面板，面板里只有名字和符号：量子比特（0 与 1 的叠加）、量子电路（旋转门、耦合门、测量）、读出（每个量子比特一个 −1 到 +1 的值，组成 n 维向量）。图的 TikZ 源放在本地构建目录 `pr-building/figures/`，xelatex 编译后转 PNG。这一节的落点是读出向量在模型里是什么，诚实转折（读出可以经典闭式计算，所以不声称量子优越性）也放在这里，全文只说一次。小节标题就写概念，例如「量子比特、电路与读出」；「量子读出把隐藏状态变成非线性表示」这种句子式标题被作者问「这句是人话？」

被否掉的写法：谈 AGI 是圣杯、想象一下未来、回顾 Anthropic 与 OpenAI 的产品，三段四百余字之后才说出本文讲什么。这一版 OSCAR 开头印在了已发表的稿件里，作者事后的评价是「too verbose, we need insight」。

**这几轮的走向本身就是规则：每一条只针对一个维度的修改指令，都会把另一个维度推出范围。** 只要求「短段落」的第二轮把段落改对了，正文却缩到一半，连接词降到 0，数字密度升到 83；第三轮补解释把它们拉回来；终稿补回精确差值，数字又升上去。所以每一轮都要在全部维度上重量一次，而不是只看这一轮要改的那一项。第五轮换成作者定的跨领域开头并加入门小节，正文长度第一次落到语料中位数附近，连接词也回到语料水平。

读这张表要分清两类偏差：
- **节奏类**（段落长度、超长段落比例、加粗密度、英文词密度、连接词密度）应该落在语料的四分位范围里。初稿最常见的错是段落太长、连接词删光。连接词为零读起来是「生硬、毫无逻辑」，作者正是这么评价的；而 `writing-style-zh` 的规则只说连接词不要堆，不是说删光。
- **内容类**（数字密度、图的密度）受论文本身影响。每个模型名、每个宽度都算一个数，一篇讲 16、32、64 比特的论文天然比语料多数字。目标是去掉不撑结论的数，不是硬凑语料的值。

**短段不等于碎句。** 每段一到两句，但每段都要接住上一段留下的东西，这一点靠连接词和指代，不靠段落长度。

**作者要求简洁时，字数让位于作者。** 语料中位数约 2400 字是参照，不是指标：作者连说三遍「简洁」之后，正文压到约 1000 字、开头约 200 字。压缩的办法是删重复、删过渡句、删不撑结论的数、一节只讲它的图，解释和例子保留，不要把机制压成一串数。

**正文太短和数字太密是同一个病。** 初稿把每个机制压成一句、把每个结果写成一串数，于是长度只有语料一半、数字密度是语料八倍。补救是加解释和具体例子，不是加数：同一个位置第一步还是 `[m]`、几步后变成一个词这种例子，一个比喻（全文最多一个，只花在第一次介绍核心机制的地方），以及论文里能讲成故事的统计。

## 数字：只留撑起结论的那几个

主表和曲线已经作为图片放在文中，读者能看到每一个数。正文只留撑起结论的数：
- 标题级结果一个，加粗。
- 它的主要对照一到两个。
- 负结果一个（见下一节）。
- 机制的一组关键对比（例如新结构与基线结构在一个关键量上差了多少个数量级）。

**按配置逐个列出的三联数改写成端点或趋势**，「差距从最窄配置的 a 分拉大到最宽配置的 b 分」。同一段里出现三组以上数，就是在念表。

## 卖点：能夸到哪，从哪一步起算编

作者要的是标题党，「even overclaim it」。松的是语气，事实集合一个字都不能动。

**可以做：** 挑最大的数当标题；用问句标题制造悬念（「被量子加速了？」「进入量子时代？」）；用「反超」「甩开」修饰一个真实的数；把论文里一句谨慎的结论说成肯定句；选最有利的对照当主对照；不在标题和开头提局限。

**不可以做，这些是编：**
- 造一个论文里没有的数，或改掉一个数的条件。真实发生过的三种：把一个只相对基线 A 成立的数据量对比，挂到对更大模型 B 的比较后面；把一个换到真实硬件后已经不再领先的结果写成「保留了领先」；把对一类方法中较弱变体的差距，写成对这一类方法整体的差距。
- 正文里暗示论文明确不声称的东西。量子类论文写着不声称量子优势，正文就要有一句这么说，只写一句，不写成辩解。标题的问句钩子可以挑逗，正文不能接着挑逗。
- 隐瞒与标题直接冲突的负结果。最窄配置不如基线，正文就写一次，带上那个差值。
- 写事实清单之外的因果（「较窄的分支尚未补回新增结构带来的差距」）和替读者下的结论（「这条曲线说明……」「共同表明……」）。

**硬件与产品用厂商的公开名字，不用内部代号。** `ibm_quebec` 是 IBM Quantum 平台上的 backend 名，读者不知道是什么，作者要求换成宣传名。换之前先查这个代号对应的处理器族与比特数：IBM 文档里 `ibm_quebec` 是 127 比特的 Eagle r3，156 比特的是 Heron r2。代号与论文写的规格对不上时，**写不带族名的规格**（「IBM 156 量子比特超导量子计算机」），把冲突交给作者决定，不要替作者选一个名字。

**判断方法：这句话被竞争对手逐句核对，哪一句会让作者需要解释？** 强度词不需要解释，改过条件的数需要。

## 图：全部从论文里裁

**不重画任何东西。** 论文截图、机制图、结果表、曲线都已经在论文里，`crop_paper.py` 裁出来：

| 种类 | 用法 | 说明 |
|---|---|---|
| `header` | 论文截图 | 第一页，从标题到作者单位邮箱，停在 Abstract 之上 |
| `figure` | 仓库里独立的图 PDF | 首选：没有页面杂物，不会带进相邻文字 |
| `figure` + `region` | 多面板图里的一个面板 | 按页面比例给框，**必须目检**，面板边界不自动检测 |
| `float` | 只存在于编译后论文里的图或表 | 按英文图注定位，英文图注被裁掉；图在图注上方、表在图注下方 |

裁 `float` 时有两个坑，都在真实一轮里碰到过：矢量图里的节点标签也是文本块，所以「图注上方最近的文本块」往往是图里的一个标签，要按宽度和长度区分正文段落；并排的两个表共享一个页面带，要把裁切框限制在本图注所在的栏里。

**从 arXiv 上的 PDF 裁，不从本地编译的 PDF 裁。** 本地稿件在投稿后还会改：一次真实的情况是，正文用到的一张方法图只存在于本地新版里，arXiv v1 根本没有，读者点进链接会找不到。arXiv 提供的每个 PDF 左侧都印着一条竖排的编号戳（`arXiv:2609.xxxxx [quant-ph] 21 Sep 2026`），它是一个又高又窄的文本块，不排除的话会把论文截图一路拖到摘要以下。`crop_paper.py` 已经把它当页面杂物排除。

**多面板图拆成面板，各放在讲它的地方。** `float` 加 `region` 按图注定位后再按比例取一块：总览图的 (a) 放在架构那一条，(b) 放在超网络那一条，(c) 放进入门小节。不要先放整张图、后面又放它的一个面板。

**`region` 是页面框的比例，`content_region` 是裁好后图像的比例。** 图比版心窄时，浮动体的页面框比图宽，按页面框取「左边三分之一」会取到空白；这时用 `content_region`。面板字母（「(b)」）和刻度标签挤在同一行、裁不掉时，用 `mask` 把那一小块涂白，只用于字母，不涂数据。

**删掉的代号会从图里回来。** 正文不写 `ibm_quebec` 以后，真机图的一个面板图例里仍然印着「Executed on ibm_quebec」。裁图要连图里的字一起查，只保留讲到的那个面板。

**图号在拼装时按出现顺序自动编**（图 1 是论文截图），不要信稿子里手写的图号，插一张图就全部错位。

**自己画的示意图和正文一样要过事实审稿。** 一张入门电路图从 |0⟩ 出发只画了 R_z 与 R_zz 两种对角门，作用在 |0…0⟩ 上只多出一个相位，每个 ⟨Z⟩ 都恒为 +1，而图里的读出条有正有负。物理上错了，是审稿的事实视角发现的，补上前后两层 H 门才对。示意图简化可以，简化到错不行。

**每张图裁完都要打开看。** 能跑通的裁切和裁对了的裁切是两回事。

图注是名词短语，编号连续（图 1 是论文截图），用正文的中文写法，正文把「固定 ansatz」改成「固定电路」后图注也要跟着改。每个机制条目后面紧跟它的图，正文里的关键对比要有图承接，必要时从多面板图里单独裁出那个面板。

## 核对：四个视角的对抗审稿

一份「看起来对」的稿子，第一次四视角审稿就挑出了三处事实错误，全是改了条件的数（见上一节的三种），其中一处会直接毁掉标题。所以每次大改之后都跑一次：

| 视角 | 查什么 |
|---|---|
| 事实 | 每个数、每个对照、每句解释，对照事实清单，清单没写的对照论文源文件 |
| 文字 | `writing-style-zh` 全部规则，加上一个对象一个名字 |
| 逻辑 | 段与段是否接住上一段留下的东西，有没有重复，结语是否承接 |
| 文体 | 对照语料：首屏、小标题、段落长度、最强的数是否加粗且靠前 |

然后一个**裁判**逐条核对：引文不在稿子里的、复核不成立的一律丢掉，合并重复，按严重程度排序，写成一份给 writer 的修订简报。第一轮 83 条意见，裁判留下 21 条，丢掉的里面有审稿人自己超出事实清单的改法。

**简报和语料统计一起交给 writer**，事实错误靠简报，节奏偏差靠统计，两者分别修不全。

## 构建与工具链

```sh
cd pr-building && ./build.sh        # 裁图 → 拼源文件 → 每个版本一份 .docx 和 .pdf
```

源文件格式见 `scripts/build_article.py` 的说明：`@title`、`@subtitle`、`@intro`、`@image 路径 | 图注 | 宽度`、`@paper`、`## `、`### `、`1、`、`@end`，正文里 `**加粗**`、`^{上标}`、`_{下标}`。

- **上标用 `^{…}` 标记，不用 Unicode 上标字符。** Noto Sans SC 没有 `⁻` `⁰` 这类字形，`10^(-20)` 会原样印出来。
- **PDF 走 xelatex + xeCJK，不走 soffice。** 只装了 Draw/Impress 的 LibreOffice 在 `share/registry/` 里没有 `writer.xcd`，任何 `.docx` 都读不进，连一行字的也一样，报 `Error: source file could not be loaded`。
- **字体**：`Noto Sans SC`，脚本缺字体时自动下载，缓存在 `$DEVTOOLS_HOME/fonts`，因为 `~/.fonts` 在容器文件系统里，重启就没了。
- **核对中文真的渲染了**：xelatex 日志里 `Missing character` 必须为 0，并从 PDF 的 ToUnicode 表里读出 CJK 码点。数 `/BaseFont` 不可靠，对象流是压缩的。脚本两项都查，失败就退出。
- **docx 核对**：重新打开，嵌入的图片数必须等于源文件里的 `@image` 数。
- **不要把 xeCJK 的 `CJKecglue` 设成空**，中英文之间的间距会时有时无。
- **标题、副标题、小标题、图注要单独设行距**，否则正文的 1.6 倍行距会让折行的标题中间空出一大块。
- **图和图注装进同一个 minipage**，否则分页会把图注甩到下一页顶上。
- **小标题不留在页底**：标题前留出约 0.4 倍版心（`needspace`），后面接 `\nopagebreak`，否则标题在上一页底、它的图和正文在下一页。
- **图注编号由拼装脚本统一加**，不管 writer 给没给编号；writer 的图注只写名词短语。只替换已有编号的写法会让没编号的图注光着出去。
- **每次构建先清掉旧的 `src_v*.txt`**，否则删掉的版本会复活。
- **论文信息块左对齐**：不可断行的英文论文题目会逼两端对齐把「论文题目」拉成「论 文 题 目」。
- **图片高度上限约 0.34 倍版心**：放不下的图会整张跳到下一页，留下半页空白。

## 语料：本地全文，提交派生物

这个 skill 所在的仓库是公开的，而量子位稿件末尾印着「版权所有，未经授权不得以任何形式转载及使用」。所以：
- **全文**存在 `references/corpus/<来源>/*.txt`，gitignore，只在本地。参考集约 30 篇，是通用 AI 的宣传稿，侧重大模型智能体、递归自我改进与智能体记忆，不按某一篇论文的题材收（量子类稿件只在写量子论文时临时参考）。不进参考集的全文放在 `corpus/_unused/`，统计跳过以下划线开头的目录。
- **提交的是派生物**：统计报告、结构记录、标题、开头两句的原文、URL。

**未发表论文的稿件也不进这个仓库。** 宣传稿里有论文的结果和作者，论文还没上 arXiv 时放进公开仓库就是提前公开。项目自己的稿件留在项目仓库的 `pr-building/` 里。

采集用工作流并行：每个来源一个采集者，全文必须用 curl 抓原始 HTML 再抽取，WebFetch 只用来找链接，因为它会转述；最后一个完整性审查逐个文件复查是不是全文、结尾在不在、抽两段对照原网页。每个文件头部记录 `popularity`，找不到真实的阅读数就写 none found，不许编。

## 平台：公众号与小红书相反

| | 公众号（量子位 / 机器之心 / 新智元） | 小红书 |
|---|---|---|
| 标题 | 中位数约 34 字，可带副标题 | 20 字以内 |
| 夸张标题 | 风格的一部分 | **会压推流** |
| 段落 | 中位数 50 到 80 字 | 每段不超过 3 行 |
| emoji | 基本不用 | 每段 1 到 2 个 |
| 结构 | 小标题分节，方法节编号 | 封面 + 分点 + 5 到 10 个标签 |

**「卖得更硬」只对公众号成立。** 投小红书要另写一版，标题收敛、正文切碎、加 emoji 和标签。

## 流程

1. **事实清单**：每个数带条件（哪个配置、对哪个基线、哪个子集），负结果和论文明确不声称的写进去。审稿发现清单不准时，以论文为准修清单。
2. **标题**：writer 出二十个，挑三个不同角度，各配开头。审长度、条件、歧义、领域。
3. **正文**：writer 按骨架写，图位写成 `[图:键名|图注]`。
4. **裁图**：`crop_paper.py batch crops.json`，逐张目检。
5. **构建**：`build.sh`，看首屏和每一页。
6. **审稿**：四视角加裁判，简报交 writer。
7. **量**：`corpus_stats.py --draft src_v*.txt`，偏差交 writer。
8. 大改后回到 6。
9. 只提交 `PR/*.docx` 与 `PR/*.pdf`。

## Rules
1. **前置结构照已发表的 AIxiv 稿件**：标题、`——` 副标题、整段加粗的作者简介、开头、论文截图、`- 论文题目` 与 `- 论文链接` 列表。
2. **标题由 writer 生成，交付几个完整版本，文章里不留候选。**
3. **目标值来自语料统计**，稿件改完要用 `corpus_stats.py` 量一次。
4. **正文只留撑起结论的数**，三联数写成端点或趋势。
5. **每个比较都带条件**，标题里的「超过」写出是哪个配置。
6. **负结果写一次，带差值**；论文不声称的，正文写一句。
7. **图全部从论文裁，逐张目检**，英文图注裁掉，中文图注是编号的名词短语。
8. **每次大改后跑四视角审稿加裁判。**
9. **只同步 `.docx` 与 `.pdf`**，源文件与裁图留在本地构建目录。
10. **语料全文与未发表论文的稿件都不进公开仓库。**
11. **先打开 arXiv 列表页确认链接**，查不到就问作者；真的没上线才写「即将发布」，绝不编号。
12. **作者选定标题后只交一个版本，文件名不带版本号。**
13. **小节标题是名词短语**（`docs-slides` 研究报告写法），不是结论句。
14. **跨领域论文的入门小节配自己画的概念图**，不用论文图。
15. **硬件写厂商公开名字或不带族名的规格**，不写内部 backend 代号；代号与规格冲突时交给作者。
16. **引用一场争论就写出对方说了什么。**

## Anti-patterns
- **AGI 圣杯开场。** 四百字之后读者还不知道这篇讲什么，而且这样的开头真的印出去了。
- **念表。** 一段三组数、每个宽度一个数，读者划走。初稿的数字密度是语料八倍。
- **删光连接词。** 为了躲「连接词堆叠」把它们删到零，读起来生硬。
- **一篇文章里三个候选标题。** 作者要的是三份完整的稿子。
- **agent 自己写标题。**
- **改了条件的数。** 数据量对比挂错了对照，真机结果写成仍然领先。
- **凭印象定目标。** 「量子位段落短」是对的，「多短」要量：47 字。
- **把未发表论文的稿件提交到公开仓库。**
- **只看裁切脚本的退出码。** 第一次裁出的两张图是 286×12 和 959×26 的细条，脚本照样成功退出。
- **结论式小标题。** 「量子读出把隐藏状态变成非线性表示」被作者问「这句是人话？」
- **内部代号。** `ibm_quebec` 出现在正文里，读者不知道是什么，而且它其实是 127 比特的处理器。
- **只说对方质疑，不说怎么质疑。**
- **把论文的专业图当入门图。**
- **改动 SKILL.md 时按字符串第一次出现的位置剪切。** 一次替换统计表的脚本从文件里第一次出现的「语料：」剪到表头，而那个词先出现在目录里，结果删掉了五个小节、57 行并推送了出去。替换要锚定在唯一的标记上，写完逐个核对小节标题还在。
- **豆腐块 PDF。** 没有 CJK 字体时 xelatex 和 soffice 都照样成功。
