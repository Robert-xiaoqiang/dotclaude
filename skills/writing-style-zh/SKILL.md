# Skill: writing-style-zh

## Purpose
用户的中文文档风格规则，`writing-style` 的中文对应版。两者分工干净：**`writing-style` 管英文交付物，这份管中文交付物，互不覆盖。** 一份文档只走其中一份。

用户要的是读起来连贯的书面中文，不是被标点和列表切碎的文字。自造比喻、反射式强调、堆叠的连接词、半译的术语都让段落显得有文采，实际在降低信息密度，也是通用 AI 输出最好认的默认。这里的每条规则都来自一份被作者退回的稿子。会话和日志是工作文本，不是交付物，所以刻意不管。

## When to Use
- 写或改一份用户会留存、会发出去的中文文档：周报、报告、设计文档、README、提案、中文讲稿的页面文字与备注、中文简历的正文。文字本身就是交付物时，这些规则生效。讲稿备注是要念出来的，它的语域按 `docs-slides`，用词规则仍按这份。
- 一份中文稿读起来像翻译、像口头讲解，或者满是自造的比喻与短标签。
- 一个术语在中英两个版本里写法不一（`训练时 harness` 对 `training-time harness`），或同一个对象在文档里有几种叫法。
- 作者口述或贴来一段中文要放进文档，或要求把它润色、改写、挤进版面，或一段话的最后一行只剩两三个字。

**不适用于：**
- 会话里的回复，以及聊天中的任何输入输出。
- commit message、PR 描述等版本控制文本，那些走 `git-commit`。
- 代码、代码注释，以及用户指定了形状的配置与数据。
- 日志、终端输出等给机器看的文本。
- **英文文档**，那些走 `writing-style`。
- 幻灯片与简历专属的规则：页面标题选断言还是名词短语、页数与压缩、简历的一页与两页版式、链接、中英两版的打包，分别走 `docs-slides` 与 `docs-resume`。这两类交付物里的中文行文仍按这份走。
- 文档的内容与论证结构，走 `writing-paper`、`writing-literature`。

## 标点与格式

### 中文标点

中文句子用 `，。、（）——`。半角 `,` `.` `( )` 出现在中文句子里充当标点，是串味的最早信号，扫一遍改掉。数字（`4.0`、`46.77`）、英文原文、代码与公式里的半角符号不是中文标点，不在此列。

### 破折号成对

**破折号是成对的「——」，孤立的 `—` 永远不对。** 表格里表示「无此项」也别用 `—`，写「无」或写出实际取值。

### 破折号的预算

**「——」约每 1,000 字一个。** 实测：human 版 0.25/1,000，drafted 版 1.78。
逐句测更准：**破折号从句必须带一个整句别处没有的数字、名字或机制**。drafted 版 61% 的破折号从句一个数字都没有，它们只是在概括前半句。删的是整个从句，不是那两个横杠。

| | |
|---|---|
| ✗ `——不干预，这条轴自己会烂掉` | 前一句的概括 |
| ✗ `——这就是它只涨 .011 的原因` | 这个数字句子里已经有了 |
| ✓ `——正好一半` | 一个读者本来得自己算的比例 |

### 一份文档一种语言

不是每节一种，是整份一种。中文文档里出现一整段英文，就是这条要防的。哪个词用中文、哪个词用英文，见「术语的中英取舍」，那里有四问的判定顺序。

### 不用「·」「/」「／」分隔名称

**这条管的是分隔符：一个「·」「/」「／」夹在两个名称或两个字段之间。** 正文、标题、署名与机构行都一样：这几个符号在 CJK 字形旁边渲染得过大，与中文、英文都格格不入。作者读到「机构甲 ／ 大学乙」时的评价是「严重问题，渲染太丑了，用逗号」，后来对整份展示里的斜线说「太大了，显得和文字格格不入」，又在另一页说「slash渲染很不对，用逗号」；中点则是直接禁掉的。列举用顿号，两个名称之间用逗号或「与」，注解用括号，署名一行一个事实；简历联系方式一行的分隔见 `docs-resume`。

| ✗ | ✓ |
|---|---|
| `机构甲 ／ 大学乙` | `机构甲，大学乙`，或 `机构甲与大学乙` |
| `背景 · 方法 · 结果` | `背景、方法与结果` |
| `单任务的 X / 跨任务的 Y` | `单任务的 X、跨任务的 Y` |

**外国人名音译里的间隔号不是分隔符。** `贝尔纳·阿尔诺` 是一个名字，「·」在名字内部、两侧不留空格，这是标准中文标点，改成逗号反而把一个人拆成了两个。分数（`7/8`）、网址、路径与代码里的「/」也不是分隔符。交付前这样查，`docs-slides` 的门禁用的是同一个范围：

```bash
# 两侧有空格的「·」、贴着字母或数字的「·」、\cdot、全角斜线、中文或英文名称之间的半角斜线
grep -nP ' ·|· |(?<=[A-Za-z0-9）)])·|·(?=[A-Za-z0-9（(])|\\cdot|／|(?<=\p{Han}) ?/ ?(?=[\p{Han}A-Za-z])|(?<=[A-Za-z]) ?/ ?(?=\p{Han})|(?<=[a-z])/(?=[a-z])' draft.md
```

命中逐条读：落在代码、网址或路径里的不改，其余全改。两个汉字之间不留空格的「·」这条命令不抓，因为它多半是音译人名；遇到 `背景·方法` 这种两个字段之间的，照样改。

这份 skill 自己用「/」「／」隔开几个候选词，那是给 agent 看的标记，不是交付物。

## 少用的词

### 一、AI 腔与公文腔

和 `writing-style` 的英文清单一一对应，中文里的常见形态：

| ✗ | ✓ |
|---|---|
| 深入探讨 / 深入剖析 | 看 / 分析 |
| 利用 / 借助 | 用 |
| 赋能 / 助力 | 让…能做什么 / 帮 |
| 展现 / 彰显 / 凸显 | 展示 / 说明 / 指出 |
| 印证了 / 是…的有力证明 | 说明 |
| 无缝 | 顺畅 / 不需要额外步骤 |
| 颠覆性 / 前沿 / 业界领先 | 说清变了什么、新在哪 |
| 拥有 | 有 |
| 为了…而… / 由于…的原因 | 为了 / 因为 |
| 开启…之旅 / 图景 / 日新月异 / 驾驭复杂性 | 写成大白话 |
| 底座 / 基底（比喻义） | 基础 / 那一层 |
| 综合来看 / 总的来说 | 直接说证据显示什么 |
| 格局 / 版图（比喻义） | 这一领域 |
| 至关重要 / 关键性 | 关键，或说清它改变了什么 |
| 账本（比喻义） | 记录 / log / 文件名 |
| 阶梯 / 台阶（比喻义） | 按真正变化的那一维给每一级命名 |
| 抓手 / 闭环 / 打法 / 颗粒度 | 说出实际动作 |
| 旨在 | 为了 |
| 一系列 | 写出具体是哪几个 |
| 极大地 | 说清幅度 |

有两条只能靠读，grep 分不出词义，所以不列进表，也不进下面的 grep：「未来」「接下来」含糊指时间时，写「下一步」或写出具体时间；「显著地」只在统计意义上用，其余写出幅度。

技术词保留原义。`robust`、`significant`、`comprehensive`、`novel`、`scalable` 这些在 ML 写作里带精确断言，该用就用；只在它们退化成空泛褒奖时才避开，**永远不要为了躲一个填充词而丢掉一个正确的技术词**。

### 二、反射式强调

实测：与同期 human 版对照，「唯一」9x、「本身（就）」9x、「正是」5x、「真正」6x。次周的一对上差距已经收平——唯一 3.4 vs 3.5 每万字，正是与真正两边都是 0——所以这一组按维护对待，不当活跃缺陷。

问题从来是密度，不是任何单个实例：「唯一算失败的一类」是一个真的、可核对的唯一性断言，但每三句就自证一次「这才是那个唯一的 X」，读者会把所有的都打折，包括真正承重的那些。**写完一节数一遍这四个词，超过一个还活着的就砍到信息量最大的那个。**

| ✗ | ✓ |
|---|---|
| 真正 | 删掉，或说清具体是什么让这个断言成立 |
| 唯一 / 正是 / 本身（就），当默认强调用 | 只在句子确实是唯一性或同一性断言时留 |

### 三、研究文档里不用的词

这一组来自 RL 与 agent 方向的报告、答辩稿和简历，每个词都被作者在稿子里点名退回过。

| ✗ | ✓ |
|---|---|
| 诚实清单 | 本周结论与未决项 / 已有与未有 |
| 我们在哪里 / 这条线在追什么 | 直接说位置，或直接提出问题 |
| 判读 | 结果 |
| 判定（指 judge 给出的结果） | 打分结果 |
| 读法（指「该怎么理解这个结果」） | 删掉这一栏，把话并进它右边那一栏 |
| 测到的 X / 量到的 X（X 本身就是测量结果） | X |
| 别处 / 那个 / 那条（指一个有名字的对象） | 写出名字，或用「其」接在名字后面。「它」grep 不出来，按「指代词不是名字」逐句读 |
| 跑 N 个 epoch / 跑一遍（指训练或推理） | 训练 N 个 epoch / 推理一遍 |
| 落差 | `gap` |
| 尺子 / 判据 | `rubric`；单条时 `criterion`，复数 `criteria` |
| 拐杖 | `guidance` |
| 形状（指一串状态的走法） | 模式，或 `pattern` |
| 读数 | 直接写这个量的名字，如 `Δ_g` |
| 门槛 / 抬门槛 | `criterion` 的要求 / 把 `rubric` 写得更严 |
| 通道 | 方案，或直接说 guidance 与 rubric |
| 命中位 | 该 rollout 是否满足该 `criterion` |
| 界（作「上界/取值范围」用） | 取值范围，或 `bound` |
| 改写（指「由 criterion 改写而来」这类说不清改了什么的用法） | 写出具体操作与保留了什么：「由 criterion 转成过程要求，不带原文」 |
| 同类 / 相似（指检索的匹配条件） | 写出检索键：语义检索、同一 criterion family、同一 domain |
| 回灌（指把结果送回上游） | 返回，或 `feed back` |
| 挡住 / 拦下（指某类失败没有发生） | 说清机制：…都会返回规划，所以这类失败归零 |
| 够不着 / 够不到（指某个手段作用不到某个对象） | 说清这个手段改的是什么：guidance 改的是提示，不改变样本难度 |
| 护栏 | 直接写出约束 |
| 压下 / 抬高（指某个指标的升降） | 下降 / 上升，并写出是什么引起的 |
| 口径（任何用法） | 评价方式 / 评分标准 / 统一的评价方式 |
| 实测 | 跑过 |
| 推演 / 投影 | 没跑，按 X 换算 |
| 命中矩阵 | judge 逐条 `criterion` 的打分结果 |
| 命中 / 未命中 / 命中率（指 `criterion` 是否成立） | 满足 / 未满足 / 满足率 |
| 档 / 档位（指一个取值来自哪里） | 直接叫它的名字：on-policy 来源、hindsight 来源 |
| 重打分 / 重采 / 重采出的 | `re-grade` / `re-sample` |
| 再判一次 | 第二次调用重新决定 |
| 预研诊断 / 折算 / 本消融的 base 行 | 见下面「内部报告的结构和词都不进对外文档」 |
| 逐字照抄 / 原样照抄（作标签或引导语） | 直接把原文摆出来，不必宣告它是原文 |
| 判平局 / 判负 / 判胜（指打分结果） | 打分相同 / 得分更低 / 得分更高 |
| 借 / 外借（指从别处取一条参考） | 取自 / 检索自，并写出取自哪里 |
| 翻过来 / 翻上去（指指标由低变高） | 从 0.12 提到 0.88 / 第一次到 7/8 |
| 这一档 / 那一档（指某个取值或来源） | 点名它：on-policy 来源、hindsight 来源 |
| 另一条 / 另一条题（指一个有标识的对象） | 写出它的标识：prompt `q7e1c`、第二个 checkpoint |
| 一道题 / 每题 / 题目（指一个不是题目的数据单元：prompt、任务输入、一段对话） | 用这份文档选定的名字，全文统一替换，如样本、任务输入。GSM8K、MATH 这类数学与考试 benchmark 的文档不跑这一行，那里的数据单元本来就叫题 |
| 判 / 被判 / 判为（指 judge 的输出） | 打分 / 得分 / 打分结果 |
| 量 / 量一次（作动词） | 衡量 / 反映：「衡量这次更新的影响」「反映的是区分度」 |
| 端口（指训练配置里的一部分） | 组件，或直接写 guidance、rubric、样本权重；表头没有合适的词就留空 |
| 三侧都开 / 两个都开 | 写出组合：`w + g + c` 同时演化 |
| 对着（X 问题） | 解决 X 问题 |
| 落点（指一次改动作用在哪里） | 被改动的字段名，以及修改后的原文：「本次改动的 `<field>`，以及修改后的 rubric 原文」 |
| 推成 / 不推 / 往 X 推（作控制动作的标签） | 点名动作：升一级、降一级、撤回；或写出效果。「推向」不在模式里，见表下 |
| 管（指控制一个量，如「管每步走多深」） | 控制 |
| 编排（指更新训练配置） | 进化加对象：进化 reward、进化任务、进化样本 |
| 买（指付出代价换来收益） | 换来 / 带来 |
| 倒推 | 写出推导过程 |
| 旁线 | 删掉这个词，把这一项与主线接起来 |
| 主笔 | 负责 / 主导 X 章节 |

表里有不少行只禁一个词义：「题」在「问题」「标题」里是标准词，「量」在「衡量」里是这张表自己给的替换，「推」在「推理期」里是核心术语。词义本身 grep 不出来，所以**每一条这样的禁令都写成一条只抓被禁形状的模式，禁令就是那条模式**；找不出这样一条模式的词不进表（「它」「未来」「显著地」就是这样移到表外的），这样才不违反下面第四小节。交付前跑这三条：

```bash
# 表一与表三里任何词义都不进交付物的词
grep -nP '深入探讨|深入剖析|利用|借助|赋能|助力|展现|彰显|凸显|印证了|有力证明|无缝|颠覆性|前沿|业界领先|拥有|开启[^，。]{0,10}之旅|图景|日新月异|驾驭复杂性|底座|基底|格局|版图|综合来看|总的来说|至关重要|关键性|账本|阶梯|台阶|抓手|闭环|打法|颗粒度|旨在|一系列|极大地|为了[^，。；]{1,20}而|由于[^，。；]{1,20}的原因' draft.md
grep -nP '诚实清单|我们在哪里|这条线在追什么|判读|读法|测到的|量到的|别处|那个|那条|跑一遍|落差|尺子|判据|拐杖|读数|门槛|命中位|回灌|够不着|够不到|挡住|拦下|护栏|压下|抬高|口径|实测|推演|命中矩阵|重打分|重采|再判一次|预研诊断|折算|base 行|逐字照抄|原样照抄|外借|都开|对着|落点|倒推|旁线|主笔' draft.md
# 表三里只禁一个词义的行，每条模式只抓被禁的那个形状
grep -nP '判定(为|结果)|跑 ?[0-9一二两三四五六七八九十几N]+ ?个? ?epoch|(轨迹|曲线|走势|序列|状态)的?形状|[两三几这那每]条通道|的界(?![面限线])|界为|改写而来|由[^，。]{1,20}改写|(满足|检索|匹配)[^，。]{0,4}(同类|相似)|投影(值|得到|出的)|[／/、] ?投影|(?<!缓存)(?<!检索)命中|档位|[这那每]一档|[一二两三四五六七八九十几]档|[A-Za-z0-9-] ?档(?!案)|被判|判为|判 ?[0-9]+ ?分|判(平局|负|胜|出)|再判|(?<![凭假])借(?![鉴口])|翻(过来|上去|到|成)|另一条|一道题|每道?题|这道题|(?<!论文)题目|(?<![衡测计估考度数质能变容重流向])量(出|一次|一下|的是)|先量|端口(?! ?[:：]? ?[0-9])|推成|(?<!类)不推(?![荐理导广进断测动出])|往[^，。]{0,16}推(?![向理导广荐进出断测演动])|(?<![主监保尽不只])管(?![理线道控辖制])|(?<!容器)编排|(?<!购)买' draft.md
```

**交付标准是三条都零命中，命中逐条读过再改，不按命中批量删。** 模式抓的是形状，偶尔会抓到一处原文引文或代码里的词，那一处读过、确认不是交付文字就留；其余每处按表里的 ✓ 改，改完再跑一遍。按词义写的禁令查不了，「口径」就是这样回来了四次；按单字一刀切地删，又会把「问题」「衡量」「推理期」这些标准词一起删掉。

**检索、召回、取回不进禁表，按下面的分工选词。** 这张表从前把「取回」整个禁掉，后来又改成只禁「查找」那个词义；可是作查找讲的「取回」与作拿字段讲的「取回」是同一个字符串，grep 分不开，而作者自己两种用法都写过（「取回的上下文 c」「检索只能整条取回」）。所以它退出了表，只留下面的分工：
- **检索 / 检索得到**：按键或按相似度查找，`retrieve` 的中文，写查找这个动作时首选。「检索得到相似样本」。
- **召回**：作为一种能力的记忆召回。「检索式召回」「生成式召回」「召回的幻觉」。
- **取回**：作者两种用法都写，不禁。要说一个条目挂着的字段时，作者后来更常写「及其相应的…」：一句「取回其写法与打分结果」被他改成「及其相应的样本 query、rollout 与打分」。

**「推」的模式只抓控制动作的标签。** 「推成全 positive」「不推」「往 X 推」把一个控制动作写成了一个手势，作者明确禁过；应当点名动作（升一级、降一级、撤回），或写出效果（让该 criterion 出现正例而不全部满足）。「这样的梯度会把 policy 推向 X」是作者自己认可的句子，梯度压力用「推向」是标准说法，所以模式不抓「推向」，也不抓「推理」「推导」。

**「编排」是作者改过主意的词。** 他早期自己写过「后训练编排」，后来读到「编排反馈与样本」时说这个词不好，要「进化 reward、进化样本」。以后者为准，早期稿件里的「编排」不是先例。

**「冻结」与「噪声」从表里删掉了，两行都是过度矫正。** 这张表从前把「冻结（指参数不更新）」送去 `fixed`，那一行没有作者的原话支撑，而作者自己口述的方法段写的是「主干模型参数始终保持冻结」。`冻结` 是参数不更新的标准中文说法，禁掉它只会逼出一个夹在中文句子里的英文词。「噪声 → 噪音」那一行同理：作者自己写「片段2属于部分覆盖，对最终问答属于噪声」，贴来给文档用的段落里也是「即使记忆无关或有噪声」；他那句「（用噪音）」换掉的是「误伤」，不是「噪声」。噪声是 ML 的标准术语（噪声标签、高斯噪声、扩散模型的加噪），两个词都照用。同样的过度矫正还有「动词＋出」，见「句式」里的「动词＋出」。

### 四、一条带例外的禁令，等于没有禁令

「口径」原来是有条件禁的：作「先说 X 的口径」这类开场白时禁，作「统一口径」时保留。
结果是一份 deck 里又出现了四处——「rubric 的口径没跟上」「评价口径」「口径先于结论」
「语料与评价口径做成基础设施」，每一处都不是被禁的那个开场白，每一处都是在用一个比喻
（口径本来是枪管内径）去指一个有正经名字的东西：评价方式、评分标准。

**禁令里写例外，就是在写一条绕过它的路。** 要么这个词整个不用，要么就别列进表里。
现在「口径」按任何用法都禁。

这一条对整张表都成立：**如果要给某个词开例外，先问这个例外会不会被用来放行 80% 的实例。**
会，就把例外去掉。

## 句式

### 否定支点：不是 X，是 Y

**否定支点「不是 X，是 Y」，每份文档一次。** 实测在同一内容上 drafted 22 次对 human 1 次，每万字 9.2 对 0.9——这是唯一一条至今没有改善的用词习惯，所以给硬预算。

X 必须是**这份文档前面印过的数字或断言**，活下来的那一次是在纠正读者刚读到的一个数：「Blind 失败率不是 28.2%，是 0.41%」纠正的是上一张表刚给的数，否定在干实事。其余一律直接说 Y。**不要为了对比造一个没人相信的 X**：「这不是失败，是训练成功之后的必然代价」→「这是训练成功之后的必然代价」，后半句自己就把「不是失败」说清楚了。

### 反射式三连

**反射式三连。** 不要默认排比三项，无论是「形容词、形容词、形容词」还是三条一组的列表。换个分组，或写成一句平常话。

### 空洞的强调与对冲

**空洞的强调与对冲。** 删掉「值得注意的是」「需要指出的是」「可以看出」「显而易见」「众所周知」「或许」「可以说」，然后把观点直接说出来。

### 含糊的背书

**含糊的背书。** 不写「值得关注」「值得探索」，给出它为什么要紧的具体理由。

### 笼统的「从 X 到 Y」开场

**「从 X 到 Y」的笼统开场。** 写出实际范围。

### 连接词

**连接词是同一个毛病换件衣服。** 实测每 1,000 字：human 2.1，drafted 5.2；因为 2 对 11，所以 1 对 9，但 4 对 20。中文靠并置连接相关分句、让关系自己显出来，把「因为…所以…」写在一个读者已经看得见的关系上，读起来就是翻译腔。**先把连接词删掉，句子真的反转时再加回来。**

### 翻译腔的四个标志

**翻译腔的四个标志**：「基于…的…」堆叠、「进行了…」套在一个已经有的动词上、「其」当所有格、主语和谓语隔了半行。每句读出声，是英文句子换了中文词就重写。

### 疑问句形的标题

**疑问句形的标题与小标题，一条都不留。** 「怎么 X」「X 是什么」「为什么需要 X」「X 是否真的 Y」写成标题，等于把问题抛给读者再自己回答一遍，读者要读完整页才知道结论。一律改成陈述句：`可逆是怎么实现的` → `通过加性耦合实现可逆`；`为什么需要 JIT` → `JIT 预演的作用`；`rubric 修改是否真的改变区分度？` → `衡量 rubric 修改对区分度的影响`（注意别顺手写成「量出…」，见「动词＋出」）。「真的」「究竟」这类口语加强词同时删掉。

### 动词＋出

**不要用「动词＋出／出来」造词，也不要用「…什么」当名词短语。** 这两个形状是同一个毛病：把一个现成的双字技术动词拆成口语式的动补结构，读起来像翻译，而且往往比原词更含糊。**替换时不要顺手换成另一个同形词**——这条是从一次连环返工里记下来的：把疑问式图注「rubric 修改是否真的改变区分度？」改成「量出 rubric 修改对区分度的影响」，改完仍然是被禁的形状，正解是「衡量 rubric 修改对区分度的影响」。

| ✗ | ✓ |
|---|---|
| 量出 X 的影响 | 衡量 X 的影响 |
| 从对话里读出答案 | 答案取自对话 |
| judge 判出满足情况 | judge 给出的打分结果 |
| 从轨迹蒸出 hint | 从轨迹蒸馏 hint |
| 新域上跑出的轨迹 | 新域上的轨迹 |
| 正文只写出这四个数 | 正文中出现的数只有这四个 |
| 先出决策 token 再出内容 | 先输出决策 token，再输出内容 |
| 决定给什么样本、什么 rubric | 决定下一步的样本与 rubric |
| 调用时生成什么 | 调用时的生成内容 |
| 只考虑如何编码 | 只优化编码 |

例外只有一处：**引文里的疑问句照抄**。翻译一句原文是问句的 task query，译文当然还是问句（“What is the top-1 best-selling product in 2022.” →「2022 年销量第一的商品是什么」），这不算违规。

**禁的是临时拼出来的动补，不是现成的复合词。** 「量出」「判出」「读出」「蒸出」「跑出」「摊出」是把一个双字动词拆开临时拼的；「提出」「给出」「指出」「写出」「抽象出」「输出」是书面中文里早就有的词，作者自己也在用（「从真实场景抽象出本质问题」「给出具体的公式」「直接写出挑战」），上表 ✓ 列里的「给出」「输出」就属于这一类。**标一个「出」之前，先问这个词在普通书面中文里查不查得到：查得到就留。** 一刀切地删会把一个作者自己在用的词换成更硬的说法，这正是过度矫正。

### 不自己写结论句

**不要自己写结论句。** 「验证了 X」「说明了 X」「体现了 X」「证明了 X」——除非那句结论是**源文献自己写的**并且你能指到出处，否则它就是替读者下判断。图和数已经摆在那里，把事实说完就停。

| ✗ | ✓ |
|---|---|
| `压缩质量与检索质量同步改善，验证了「保留—检索」应联合建模。` | 删掉整句 |
| `阶段二再提高 4.0 个百分点，说明结果反馈主要学会了生成／放弃的边界。` | `阶段二在四基准均值上再提高 4.0 个百分点。` |
| `取回错误直接体现在分数上。` | 删掉；上一句已经说了打分方式 |

### 图已经说过的不再说

**图已经说过的，正文不再说一遍。** 一页里既有图又有文字时，文字承担图画不出来的那部分：取舍、评价方式、数字的来源。把方框里的名字用句子重述一遍，读者读了两遍同一件事，还占掉了本该给图的空间。实测一条 bullet 与它上方方框内文字逐字重合，删掉之后那一页才有余量。

### 书面语域

**口语词不进交付物；摘要、简历、幻灯片的页面文字与书面文档用书面语。** 「东西」「说了算」「什么都没算」「搞定」「弄」这类词在会话里没问题，写进文档就掉档次，而且往往顶掉了一个更准的技术词：「$y=x$ 永远可逆，但什么都没算」→「但没有表示能力」。同一句里把「说了算」用两次这种重复也一并去掉。

口语不止是单个词，还有整句的讲解口吻：「这项工作让模型反复回答开放式问题」「RL 里会变的不只有 policy」「另外两点值得说」都是讲台上的口头说法，它们写在幻灯片的页面上，作者读到时的评价是「有点太白话了」「现在太口语化了」。改写时的常见替换：

| ✗ | ✓ |
|---|---|
| 沉淀成 | 沉淀为 |
| 让它 | 使其 |
| 更短更省 | 路径更短、开销更低 |
| 很快失效 | 过早失效 |
| 要……（表打算）、自己转起来 | 删掉，直接写做了什么 |

书面语的样子，以作者口述替换口语稿的一段为准：「随着长期记忆不断累积，记忆规模持续增长，传统检索式记忆逐渐面临维护成本高、检索开销大等问题。这项工作探索将长期记忆的召回方式从检索式转向生成式……这一范式的核心挑战在于……」。先交代问题，再说做法，再说难点，每句都有主语。**书面不等于名词化**，见「常见的别扭句式」末尾的提醒：动词驱动的短句照样是书面语。

**讲稿备注不按这一条改写。** 备注是要念出来的，`docs-slides` 要求它写成口头的句子、技术语域：数字按念法写，一段一个意思，过渡词简单。把备注改成「使其」「沉淀为」这类书面句，念出来反而别扭。作者对「太白话」「太口语化」的批评都落在页面文字上，没有一次落在备注上。备注里仍然不用「东西」「搞定」「说了算」这类口语词，「少用的词」的 grep 也照跑。

### 否定清单

**不写「不带 X，不带 Y」这类否定清单。** 一句话说清它是什么，读者自然知道它没有什么；列举缺席项是把设计意图写成了辩解。「只引 policy 自己在同一类 criterion 上写过的话，不带数字，不带 criterion 文本」→「policy 的历史输出」。删掉「不带 xxx」，只留那个名词。

### 引了原文不再转述

**引了原文，就不再转述原文。** 原文（prompt、rollout、guidance turn、criterion）摆在引文块里，读者自己会读；在它前后加一句「thinking 把 turn 复述成核对表，正文再抄一遍同一句话」是废话，也是替读者下判断。引文块前只留一个名字或一个时间戳（`rollout（t=66）`），引文块后只写打分结果与数值。

### case 文档什么都不省

**case 文档里什么都不省。** 一个 case 要把 prompt 全文、全部 rollout（八条就八条）、全部 criteria 及其权重、每条 rollout 逐 criterion 的打分结果、以及每一步演化前后的 guidance / rubric / sample 原文都摆出来。英文原文照抄，每段原文之后紧跟一段中文翻译，用引文块分开（原文与译文的顺序见「引文先给原文，再给中文翻译」）。不要「其余类似」「略」「……」，也不要只挑最好看的一条。

### 疑问词当名词

**疑问词不能当名词用，把那个东西说出来。** 「差在哪」「改在第几条上」「取哪一段」——
把一个疑问句塞进名词的位置，读者得先在心里把它改写成陈述句才能接着读。这与「疑问句形的标题」
和「那一X 与这一X 当名词」是同一个毛病的三种形态：**句子要说出
那个东西是什么，而不是问出来。**

| ✗ | ✓ |
|---|---|
| 这些 rollout 与目标差在哪 | 这些 rollout 与目标 criterion 的差距分析 |
| policy 的历史输出与目标差在哪 | policy 的历史输出与目标的差距 |
| 这一步用的原子操作，改在第几条上 | 本次改动的 `<field>`，以及修改后的 rubric 原文 |
| 取哪一段历史 | 历史的截取范围 |
| 决定学下一条什么 | 决定下一步的样本 |
| 看这条 criterion 是不是一直是 0 | 这条 criterion 的历次打分结果 |

第三行的 ✓ 从前写的是「本次改动用的原子操作与落点」，作者读到时说它「不是人话」：「落点」不是正确的中文用法，而且被改的对象已经有字段名了。**对象有字段名，就用字段名。** 一个 ✓ 示例带着禁用词，等于在教那个错误。

**判断方法：这个短语能不能加一个问号单独成句？能就是疑问词当名词用。**
同一句里的「多少」「几个」「哪些」照此处理，除非它真的在问一个数。

### 那一X 与这一X 当名词

**「那一X」与「这一X」都不能当名词用，点名那个对象。** 「那一段」「那一块」「那一列」「那一行」
「那一组」「那一份」「那一条」「那一个」这一类，读者必须回头去数才知道指的是谁，而写的人
当时是看着图或表写的，所以自己不觉得有歧义。**改法不是换一个指示词，是把对象的名字写出来。**
近指的一组同样算：「这一步」「这一条」「这一版」「这一组」在跨句、跨栏出现时，与远指没有区别，
都要换成名字（`本次改动`、`第 $k$ 条 criterion`、`当前版本`、`本组 rollout`）。

| ✗ | ✓ |
|---|---|
| 该列最高 46.77 | $\lambda_{\mathrm{step}}=2$ 这一列最高 46.77 |
| 主结果表的 46.66 就取自这一列 | 主结果表报的 46.66 就是 $\lambda_{\mathrm{step}}=2$ 时的准确率 |
| 检索得到的条目仍然是写入时的那一份 | 检索得到的条目仍然是写入时的内容 |
| 上一页那条 hint | 从成功轨迹蒸馏出的 hint |
| 这一类占三成三 | Spurious + Inversion 占 33.9% |

**例外：紧跟在被指对象后面、同一句之内的回指是可以的**，「$\lambda_{\mathrm{step}}=2$ 这一列
最高 46.77，仍低于 CoT」里的「这一列」有前文紧贴着，不必展开。跨句、跨页、跨图的一律点名。

同源的一条：**不写文档自述**。「上一页」「下一页」「本页」「如前所述」在幻灯片里尤其糟，
演讲时页序可能已经变了，读者手上也只有当前这一页。

### 取舍两侧点名，因果用动词

**写取舍时，两侧都点名，因果用动词接起来。** 一句话说「改了 A，B 变好了，C 变差了」时，
把它压缩成并置的短句，读起来是笔记而不是话。作者改写同一句时补回来的正是这三样：
**对象的英文名、这个对象是什么、以及「引起了」这个动词**。

| | |
|---|---|
| ✗ | `静态指导让 All-0 下降，但 All-1 高过 base` |
| ✓ | `静态 guidance 让 All-0 这一 pattern 下降，但在另一个方面，引起了 All-1 这一 pattern 上升的问题` |

三处差别，每一处都是一条已有规则的实例：`静态指导` 是半翻，改回 `静态 guidance`；
`All-0` 是个代号，读者需要「这一 pattern」才知道它是一类失效而不是一个数；
`但…高过 base` 只是并置，`引起了…的问题` 才说出这是前一个动作的代价。
**判断方法：这句话在说一个 trade-off 吗？是就检查有没有一个表示因果的动词。**
同一个毛病的其他形态：`压下一类就抬高另一类`、`按下葫芦浮起瓢`、`探索不足又上来`。

### 工程动作的动词

**工程动作用现成的中文动词，编不出来就用英文。** 这一条与「动词＋出」同源，但错法相反：
「动词＋出」是把双字动词拆成动补结构，这一条是给一个动作硬造一个中文比喻。

| ✗ | ✓ |
|---|---|
| 把报错回灌给规划 | 把报错**返回**规划，或 `feed back` |
| 两条反馈边把失败挡住 / 拦下 | 这两类失败归零，因为报错与验证结果都会返回规划 |
| 改 guidance 或改 rubric 都够不着 | guidance 与 rubric 改的是提示与评分标准，不改变样本难度 |
| 有一条护栏必须说 | 直接写出约束的内容 |
| 对照按机制排成阶梯 | 对照组按机制**逐级增配** |
| 先说结果的口径 | 删掉开场白，直接写评价方式 |
| 训练目标从保真换成 utility | 训练目标**从**保真**转变到** utility |

「回灌」不是中文用法，「挡住／拦下」把一个统计结果写成了打斗动作，「够不着」把一个作用范围
写成了手臂长度，读者知道这个手段没用，却不知道它改的是什么，而那是这句话唯一要说的事。
「护栏」「阶梯」是给已有名字的东西套比喻（见「别给已经有名字的东西造比喻」）。**「先说 X 的口径」「有两点」
「我要说清楚」这类交代结构的开场白一句都不要**，标题已经说了这一节写什么。

### 一句一个因果

**一句只承一个主要的因果关系，先写观察到的事实，再写解释。** 幻灯片上的句子可以短，但主语、比较对象与结论都要在。把条件、后果与机制塞进一个没有主语的冒号短语，读者要自己拆三遍；作者读到这种句子时问的是「会说人话么」，他改写时补回来的正是主语和条件。

| ✗ | ✓ |
|---|---|
| `Δ-gating：Δ<0 时内容 token 才收到梯度，错误的 generate 不会带着措辞继续优化` | `只有当生成确实比弃权更好时，内容 token 才收到梯度，否则这个 rollout 不会被优化` |

**数字是证据，数字与结论之间要有一层解释。** 往一句压缩过度的句子里再加数字修不好它，只会让它更难读。这是 `writing-chatgpt` 所说的「过早压缩」在句子层面的样子。

### 未定义的短标签

**不造听起来像洞见、却从不定义的短标签。** 「探索预算」「摊得回来」「到顶」「只增不改」「可测的量」，以及单独成行的「reward 失效是时序现象」，读者无从知道它们指什么。作者列改写原则时写的第一条就是「不要为了追求 punchline 硬造概念」。写成带主语和比较对象的平常陈述：

| ✗ | ✓ |
|---|---|
| `记忆初始化摊得回来：观测花 X 小时，换到 1.5 个 epoch 就到顶` | `memory initialization 是一次性开销，耗时 X 小时；方法在约 1.5 个 epoch 达到最佳，这部分开销相对整体训练成本不高` |
| `guidance 花掉的是探索预算，不是时间` | `guidance 不显著增加 rollout 时间，但真正用于自由探索的 rollout 比例下降` |

「别给已经有名字的东西造比喻」管的是给一个已有对象换装，这一条管的是凭空造一个对象。

### 趋势证据不写绝对词

**证据是趋势或主流做法时，不写绝对词。** 领域层面的判断里，「只能」「不再」「一律」「唯一」换成「目前主流」「比例下降」「受到约束」。绝对词一句反例就能驳倒（rubric 之前就有 reward model），作者每次读到都改。

| ✗ | ✓ |
|---|---|
| RL 只能以 judge 按 rubric 给出的分数作为 reward | RL 目前主流的做法是以 judge 按 rubric 给出的分数作为 reward |
| 被揭示的那几条不再是探索 | 真正用于自由探索的 rollout 比例下降 |
| 现有方法只更新 rubric，修不了样本选择与 rollout 探索 | 现有方法分别进化 rubric 与样本，没有统一的建模，也没有跨训练步的记忆用于归因 |

最后一行同时是一条描述前人工作的规则：**写它缺的那个机制，并对照原文核实，不写一个「只会 X」的稻草人。** 背景段写这个领域真实存在的问题（记忆规模增长、检索噪音、幻觉），不为了衬托方法造一个缺陷。同一项工作的背景被这样写错过两稿，最后是作者自己补上了准确的差距。相关工作怎么组织见 `writing-literature`。

### 兄弟条目同一个句式

**并列的兄弟条目用同一个句式。** 目录条目、概览页上每项工作的一句话介绍、一串小节标题、同一个列表里的注解，改了其中一条，其余几条跟着改成同一个形状。句式不一，读起来像从几份文档里剪下来拼的；作者多次要求「这个句式和前一句保持一致」，并口述过两条平行的范例。模板举例：

| 位置 | 句式 |
|---|---|
| 一项工作的一句话介绍 | `MethodX（会议 年份）：在<场景>中，将<A>建模为<B>，<效果>` |
| 研究线条目 | `<层级>：<方法名> <核心机制>，<作用>` |
| 一串小节标题 | `单任务的 X`、`跨任务的 Y`、`整个学习过程的 Z` |

同一组里一律中文行文，关键概念保留英文。一条中文解释后面再拖一段英文解释，也算句式不一，改成中文并对齐（见「术语的中英取舍」里的「英文只负责名字」）。

### 用机制称呼一项工作

**用听众听得懂的机制称呼一项工作，不直译标题里的比喻。** 标题里的比喻是给论文起名用的，直译成中文，听众仍不知道方法做了什么。✗ `思维电梯` ✓ `按问题难度决定推理步数的方法`。作者读到直译时的原话是「写人话」。英文简历的栏目名同理，见 `docs-resume`。

## 常见的别扭句式

下面这一组来自一次母语审稿：把一份写完的中文报告交给一个只看表达、不看技术内容的中文 judge，让它逐句挑别扭的地方。挑出来的十条集中在六个模式上，都不是用词错误，而是**句子的骨架是英文的**，所以词级的检查抓不到。

| 模式 | ✗ 原句 | ✓ 改写 |
|---|---|---|
| **「那一X」指代一个具体对象**（那一段／那一块／那一列／那一行／那一组／那一份／那一条／那一个） | $\Delta_r$ 是 rubric 变了带来的**那一段** | $\Delta_r$ 是 rubric 变化引起的**那部分分值差** |
| **句尾拖一个「…的事 / …的情况」**，英文 something that would happen 的直译 | 这恰好是 rubric 写得贴合现有回答时**会发生的事** | 这恰恰是 rubric 被写得过于贴合现有回答时的**典型结果** |
| **对话口吻混进报告** | $\Delta_g$ 的走势**要说得保守些**： | **保守地看** $\Delta_g$ 的走势： |
| **主观动词代替客观陈述** | 这与上面**批评前人**的那条…是同一个毛病 | 这与**前文指出的**「部分域缺少对应 bench」是同一个问题 |
| **搭配错误**，词选对了但不与这个宾语搭 | 分成两**族**；边际收益在**收窄**；论证会**绕回自身** | 分成两**类**；边际收益在**递减**；论证会构成**逻辑循环** |
| **半句话**，缺主语或缺谓语 | $\Delta_g$ 只要一遍重打分 | **计算** $\Delta_g$ **仅需**一次 `re-grade` |

**自查的办法：把每一句单独读出来，问它能不能独立成句、主语是谁、这个动词平时跟这个宾语搭不搭。** 这三问比任何词表都更能抓住翻译腔，因为翻译腔的病灶在结构而不在词。

**一个反向的提醒：动词驱动的句子是对的，不要为了「正式」把它们改成名词堆。** 同一次审稿里被点名夸奖的是「把它拆成两部分」「探索不足这一侧没有对应的手段」这类句子——短、有动词、没有「基于…的…」。正式不等于名词化。

## 术语的中英取舍

这一节管一个词用中文还是英文、英文名字放在句子的哪个位置，以及字段名怎么写。

### 什么时候用英文，什么时候用中文

**总原则：英文负责名字，中文负责句子。** 指称某个特定对象、机制或量的名词用英文，把它们连成句子的动词、连词与普通名词用中文。「memory 里存两样东西」「rollout 的输入分布」「$g$ 进 sampler 端」都是对的写法，英文词照常参与中文语法，不加引号也不加书名号。

四问按顺序走，第一个命中的就是答案：

| # | 问 | 命中就 | 例 |
|---|---|---|---|
| 1 | 它是标识符、字段名、专有名词或 bench 名吗 | 英文，原样照抄 | `slot_id`、`split == train`、HealthBench、MedQA |
| 2 | 这个**动作**在英文里有固定说法吗 | 英文动词 | `pull image`、`checkout` 到某个 commit、`mount`、`backward` |
| 3 | 中文里有本领域论文**真的在用**的对应词吗 | 中文 | visit → 访问；response → 回答；satisfy → 满足 |
| 4 | 以上都不是 | 英文 | rubric、criterion／criteria、guidance、policy、rollout、GRPO、advantage、harness、scope、gap |

**第 3 问卡死在「论文真的在用」，而非「翻得出来」。** rubric 翻成「评分表」翻得出来，但这一行没人这么写；advantage 翻成「优势」会与日常的优势混掉；rollout 翻成「展开」会与数学上的展开混掉。**翻得出来但没人用，或者一翻就歧义，都按第 4 问处理。**

第 2 问单独列出来，是因为**动词短语比名词更容易翻砸，而名词恰恰更容易让人以为已经守住了规则**。名词硬造出来读者还能猜，动词短语硬造出来会直接变成滑稽的画面：

| ✗ 硬翻的动词短语 | ✓ |
|---|---|
| 要拉起钉在指定 commit 的容器 | 要 `pull image`、把仓库 `checkout` 到指定 commit、起容器 |
| 把梯度打回去 | 回传梯度，或 `backward` |
| 把权重灌进去 | 加载权重，或 `load state dict` |

「拉起」「钉」「打回去」「灌」逐个看都是常用动词，凑在一起描述一个工程动作就不再是中文了。

**不要半翻。** 一个词在一份文档里只有一种写法，写完 grep 一遍确认。半翻最常见的形态不是名词，是**中文修饰语配中文中心词**：`静态指导`、`动态判据`、`初始判据`。中心词一旦落回中文，这个词就从一个查得到的名字变成了一个查不到的词组，而且同一份文档里必然会有另一处写成英文。正确形状是中文修饰语加英文中心词，中间隔一个空格：`静态 guidance`、`动态 rubric`、`初始 rubric`。

**`criterion` / `criteria` / `rubric` 一律用英文，不译成「判据」。** 这一条是纠正的，不是新增的：这份 skill 从前把 criterion 定为「判据」，而 `docs-weekly` 的 Vocabulary 一节同时把 criterion 列在「不翻译」里，两份互相矛盾了很久。矛盾是静默的，代价是一份 26 页的答辩 deck 全篇写着「判据」。作者读到时的原话是「别尼玛的叫判据了，就叫 rubric，criterion / criteria 直接」。按第 4 问处理：`rubric` 指整套评分标准，`criterion` 指其中一条，`criteria` 是复数。`docs-weekly` 那一侧是对的，以它为准。

**第 4 问的答案不是「造一个中文词」。** 四问走完还是英文时，就用英文；此时去发明「界」「命中位」「阶梯」这类说法，等于把一个能查到的词换成一个查不到的词，那是另一条规则禁止的事。

**复合概念名过三项检查。** 四问管的是单个词；一个由几个词组成的概念名，按下面三项走：

- **论文里命名过、读者可能去搜的概念，整个保留英文**：training-time harness、controllable test-time scaling、early-exit、segment。不要只把修饰部分译成中文：✗ `训练时 harness`、✗ `测试时可控性`、✗ `片段`。半译的名字与英文版对不上，读者会以为是两个东西；一份文档同时有中英两个版本时（简历、双语摘要），这一点最先暴露。作者的要求是「训练时 harness → training-time harness，中文版里保持这个概念」。
- **领域术语前的描述性修饰语可以是中文，中心词保留英文**：`反事实 rollout`、`静态 guidance`。这与上面「不要半翻」是同一条：修饰语中文，中心词英文。
- **文档自己起的标签不是术语。** 失效类别（Blind、Saturated、Spurious）、「off-policy 决策」这类混搭词，是这份文档自己造的，面向中文听众时给它一个说清整个症状的中文名：`打分没有区分度`、`打分不准`。名字要说全：「rollout 不出」不完整，「rollout 不出区分度」才是这个症状。作者在这一点上改过主意：这些标签在一份 deck 的大半里保留英文，后来才要求换成「合理的中文概念」，以后者为准。这与下面「结构性的概念可以自己起中文名」一致：自己起的名字用中文，查得到的名字用英文。

**英文只负责名字。** 名字后面的解释、注解，以及把名字连起来的分句，一律用中文；兄弟条目的注解用同一个句式（见「兄弟条目同一个句式」）。中文句子里不夹随手的英文缩写或英文填充词。作者的原话是「正经中文，不要用蹩脚的简写英文，关键概念保持英文没问题」。

### 英文进中文句子的三条位置规则

「英文负责名字，中文负责句子」说的是词该用哪种语言，下面这三条说的是它出现在句子的哪个位置。

**第一次出现：中文说这东西是什么，英文名字放在括号里。** 之后全篇用裸的英文名，不再重复中文解释。

| | |
|---|---|
| ✓ `训练历史记忆，有助于诊断（training-time memory）` | 先说它干什么，再给它的名字 |
| ✓ `更新之前先预演一遍，衡量这次更新的影响（Just-in-time guidance 与 rubric）` | 同上，括号里是这套机制在论文里的叫法 |
| ✓ `合起来记作 training-time harness 配置（non-parametric）` | 括号里补的是一个英文形容词，中文里没有等价的短说法 |
| ✗ `我们引入 training-time memory，即训练历史记忆，它有助于诊断` | 名字先行，中文成了同位语，读起来是翻译 |

**中文修饰语与英文名词之间只隔一个空格，不加「的」。** `动态 guidance`、`动态 rubric`、`当前 rollout 结果`、`初始 rubric`。写成「动态的 guidance」会把一个名字拆成一个词组。

**结构性的概念可以自己起中文名，它管辖的内容仍用英文。** `跨步记忆` 这一节里全是 hindsight、foresight、rollout；`跨步检索与跨样本检索` 这一节里全是 scope、last、window + cross_sample。中文名负责在目录里说清这一节讲什么，英文名负责在正文里指准对象。这与「别造比喻」不冲突：`跨步记忆` 命名的是这份文档自己的组织方式，不是给 memory 换个说法。

### 一个工程动作有英文原名时，别造一个中文双字词

`re-grade`（换一份 rubric 给同一批回答重新打分）与 `re-sample`（换一份 guidance
重新采一组）是这套流程里两个有名字的动作。压成「重打分」「重采」读着像速记，
而且「重采出的 $o'_t$」还犯了「动词＋出」的动补结构。这属于四问的第 2 问：**动作在英文里
有固定说法，就用英文动词。**

| ✗ | ✓ |
|---|---|
| 固定回答重打分 | 固定已记录的回答 `re-grade` |
| 按 $g'$ 重采一组 | 按 $g'$ `re-sample` 一组 |
| 重采出的 $o'_t$ | `re-sample` 得到的 $o'_t$ |
| 再判一次 | 第二次调用重新决定 |

**「档」「档位」同理，是给一个有名字的东西造的量词。** on-policy、hindsight、
foresight 本来就是三个来源的名字，写「foresight 这一档」等于先把名字收起来
再用一个量词去指它，读者要多绕一道。写 `foresight 来源`，或者直接写 `foresight`。

### 「命中」不是 criterion 的动词，「满足」才是

`criterion` 说的是一条要求成立没成立，成立就是**满足**。「命中」是打靶与检索的词
（hit rate、cache hit），拿来说一条评分要求，读者要先把它翻回「满足」才懂，而且
HealthBench 与 AMARIS 这一类工作在自己的字段里写的就是 `criteria_met`。

| ✗ | ✓ |
|---|---|
| 8 条 rollout 全部命中 | 8 条 rollout 全部满足 |
| 一条 criterion 都没命中 | 一条 criterion 都不满足 |
| 命中率 / 命中数 | 满足率 / 满足的条数 |
| 按命中率挑 targets | 按满足率挑 targets |

这一条是反过来改的：本文件的四问表从前把 `hit` 列在「中文里有对应词」那一行，
译作「命中」，于是一份 deck 里出现了十处。`hit` 在检索与缓存里确实是命中，
**但 rubric 里的那个量不是 hit，是 met**，四问的第 3 问问的也是「本领域论文真的在用
的词」——写 rubric 的论文用的是 met／satisfied。

### 字段定义：英文标识符在前，中文解释在后

一页在定义一个 prompt 或一条记录的字段时，每个字段先写它的英文标识符，放在尖括号里，再写中文解释；层级用缩进，一行一个字段：

```
<reference>：参考回答
<critique>：对当前回答的评价
    <positive>：正例，摘自 rollout 原文
    <negative>：负例，摘自 rollout 原文
```

三种写法都被作者退回过，每一种都让读者对不上代码或 prompt 里的那个字段：

| ✗ | 为什么 |
|---|---|
| 中文字段名：`正例：…`、`负例：…` | 字段在 prompt 里叫 `<positive>`，中文名在任何文件里都 grep 不到 |
| 几个字段并进一格：`<criterion / points / axis>` | 读者不知道这是一个字段还是三个，层级也丢了 |
| 在字段定义的位置写一段流程：「按 g′ re-sample 一组，没起作用就升一级……」 | 读者要的是每个字段是什么，流程属于另一页 |

**字段的取值级别也用字段自己的英文名**（`strength` 的各级），不写「档位」。作者的原话是「我们已经有了符号的字段名字了，为什么不用」。

## 一个对象一个名字

### 一个对象一个名字，一个符号一个含义

一份长文档里同一个东西被叫成四五种名字，是读者最容易被绊倒的地方，也是最容易积累的一种债。实测一份四十多页的讲稿里，同一个「被生成出来的那段文字」出现过 hint、短提示、提示 m、经验四种叫法；同一个模型出现过记忆策略 $\pi_{\mathrm{mem}}$、独立记忆模型、memory policy、$\pi_\phi$、记忆模型五种叫法。每一种单独看都合理，合在一起读者要先确认它们是不是同一个东西。

**符号比名字更严重。** 同一个字母在不同页表示不同的量，读者会把两页的结论错误地接起来。实测 $q$ 在前十页是「查询」、第十一页起变成论文里的「压缩表示」，而这两页恰好在讨论「$q\to c$ 这个方向没被训练」——读者会直接读错。改法是给其中一个换字母（压缩表示改用 $z$），不是加一句「注意此处 $q$ 含义不同」。

**写完扫一遍**：把每个反复出现的对象和符号列出来，各自只留一种写法，再全文 grep 一次。这件事晚做一天，要改的地方就多一页。

### 改名是全局替换

作者给出的一次改名（「训练期（RL）→ RL 训练期，改变所有」「题目 → 任务输入」）是一次全局替换。同一遍里改掉每一页、每个图中标签、目录条目、页脚、讲稿备注，以及由它派生的符号，然后 grep 旧写法，结果为零才算改完，汇报时给出改了几处。只改被指到的那一页，是这条规则记下来的失败：作者不得不重复「改变所有」，又在后面几页的 bullet 里把同一个旧词再标一次。英文交付物的同一条规则在 `writing-style`。

**一页上的概念词要与它的图和相邻页对齐。** 方法摘要写「编码、压缩、重建」，而图上写的是「写入」与「召回」，读者会以为是两套东西；作者问的是「压缩是从哪来的」。同一份 deck 前面写「专家 rubric」、后面写「医生写的 rubric」，同理。**符号也一样：** $p_t$ 或 $D$ 一旦换了含义，每个公式与每张图跟着更新。整份 deck 的一名到底与 grep 门禁见 `docs-slides`。

### 指代与量词要跟前文对齐

前一段说「gap 有两个**方面**」，下一句就该是「两个**方案**」。换成「两条**通道**」等于凭空引入第三套词汇，读者要先确认它跟前面是不是同一件事。**改一个名词之前，先 grep 全文看它跟谁配对。**

### 指代词不是名字

「那一X 与这一X 当名词」管的是带量词的指代，同族还有一批不带量词的：**别处、那个、那条、它**。
它们在写的人手上有明确所指，在读者手上没有——读者得回头找上一个名词，而幻灯片上很可能已经翻页了。
前三个在「少用的词」的 grep 里；「它」grep 不出所指，只能逐句读：跨了句或跨了栏的「它」，换成名字。

| ✗ | ✓ |
|---|---|
| 与本组失败 rollout 相近的答案，看它在别处按什么 rubric 得到 positive | 与本组失败 rollout 相近的 rollout，及其相应的样本 query 与 rubric |
| 目标是整列 negative 的那条 criterion | criterion $k$ |
| 取回其写法与打分结果 | 及其相应的样本 query、rollout 与打分结果 |

第二行的 ✓ 从前写的是「整列 negative 的那个 $k$」，带着「那个」；作者对原句的评价是「一点用都没有」，因为 $k$ 已经是名字。第三行是作者自己的改法（原话「及其相应的样本query，rollout, 和打分」）：「其写法」仍要读者去猜写法指什么，他把被指的对象一个个点了名。

**改法有两种：把名字写出来，或者用「其」接在名字后面。**「其」是所有格，它必须紧跟在被指对象
之后，所以不会像「它」那样跨句飘走。

### 别给已经有名字的东西造比喻

术语保持英文那条挡得住「把 rubric 翻成评分表」，挡不住这种：给一个已经有名字的对象换一个中文比喻，读起来有文采，代价是读者要先解码，而且解码出来的说法在任何论文里都查不到。

**实测：一份 drafted 报告里 落差 6 次、尺子 3 次、拐杖 1 次；同期两份 human-authored 报告里，这三个词各 0 次。**

**比喻的配额是每份文档一到两次，只花在第一次引入一个机制的地方，之后回到那东西本来的名字。** 判断方法：这个比喻是在解释一个读者还没见过的机制，还是只在替一个已有的名词换装？后者删掉。

### 打分结果用分数的说法，不要用比赛的说法

`判平局`、`判负`、`判胜`、`打成平手` 是球赛的词。judge 给出的是分数，
所以说的应该是分数怎么样。比赛词还会悄悄带进一个「两条在争胜负」的框架，
而实际上它们只是各自被独立打了一个分。

| ✗ | ✓ |
|---|---|
| $Q$ 判平局 | $Q$ 打分相同 |
| B 判负 | B 得分更低 |
| 两条打成平手 | 两条得分一样 |

### 来源标注说发生了什么，别给它起个技术名字

「实测 / 推演 / 投影」把「跑过」和「没跑」包装成两类并列的结果，读者扫过一列只看到两个技术名词，看不出后一类根本没有跑。写 **跑过** 与 **没跑，按 X 换算**，哪一行是证据、哪一行是算出来的，一眼就分得开。

「投影」还多一层毛病：中文里那是几何与光学的词，拿它指外推是硬造，而「换算」「估的」「外推」都是现成的。

## 结构、标签与数值

### 分解关系写成层级要点，不要写成连接句

一段论证如果本身是「这件事分成这几块，每块需要那个东西」，它的形状就是一棵树。把树摊平成句子，读者要自己重新把层级搭回来。

```markdown
+ 方案
    - 动态 guidance
    - 动态 rubric
+ 难点
    - 动态更新（演化）的时机：好的诊断（analyzer）
    - 动态更新（演化）的内容：好的更新（updater）
+ 动机
    - 训练历史记忆，有助于诊断（training-time memory）
    - 更新之前先预演一遍，衡量更新带来的影响（Just-in-time guidance 与 rubric）
```

八行说完「有两个方案、两个难点、两条对应的动机」，而且哪条动机对应哪个难点一眼可见。写成散文要四段，还得靠「其中」「与之对应」这类词把层级找回来。

**判断方法：这段话里有没有「A 分成 B 和 C」「B 需要 D」这样的关系？有就写成缩进。** 散文留给树画不出来的那一步——两条线索在这里合流、或者某个结论与直觉相反。

### 一条 bullet 只承一个 claim，数值挂在子级

一条 bullet 里塞进三组以上数值，读者读到第二组就在心里重排。写法是：**claim 用粗体放父级，每组数值各起一条 `-`**。

| | |
|---|---|
| ✗ | `+ **两个端口都开才三类同降**：全 0 10.5、全 1 13.4、S+I 27.2，Agree 到 48.9；它的全 0 与基线 A 的 10.0 相当，全 1 与基线 C 的 13.2 相当` |
| ✓ | `+ **两个组件同时演化，三类失效才同时下降**：`<br/>`    - MethodX 全 0 10.5、全 1 13.4、S+I 27.2，Agree 48.9`<br/>`    - 基线 B 全 0 10.9、全 1 14.3、S+I 29.3，Agree 45.5` |

这一对的 ✗ 行同时犯了「端口」「都开」两个禁用词（见「少用的词」第三张表），✓ 行一并改掉了。

### 一个数的基准写在它自己的句子里

一个数的测量条件（在哪个 checkpoint、哪一步、哪个 epoch 测的）跟着那个数走，不要抽出来单写一句挂在表前。抽出去之后，读者看某一条 bullet 时手上没有条件，还得回头找。

| | |
|---|---|
| ✗ | 表前单起一句「各 arm 的占比读在自己的 checkpoint 上」，然后 bullet 里只有裸数 |
| ✓ | `基线 A 的全 0 占比从第一个评测点的 12.3 降到 10.0，测于其第 1080 步的 checkpoint` |

### 不写文档自述，也不写内部稿件编号

**交代文档结构的句子一句都不要。**「上面四条是分类，这一节把其中一条从头走一遍」「这一节先看已有方法」「留到消融一节再引入」——标题已经说了这一节写什么，这些句子只是把标题再讲一遍。

**内部稿件的日期编号不进正文。**「0812 没有单列」「沿用 0828 的写法」「见 0902 的设计笔记」对读者是空的：他手上没有那些稿子。要引就引 arXiv 号或论文名，其余删掉。

### 标签与图注是名词短语，不是叙述句

卡片抬头、图注、表头、小标签——这些位置只放**名词短语**。写成一句带主谓或带所有格的话，
读者要先把整句读完才知道下面是什么，而这些位置存在的理由恰恰是让人不必读。

| | |
|---|---|
| ✗ | `HealthBench 的一道题与它自带的医生 rubric` |
| ✓ | `HealthBench（医疗问答任务）样例与专家 rubric 示例` |

三处差别，每处都是一条独立的毛病：

- **口语量词不当标签。**「一道题」「一条回答」「两条计划」是说话时的说法。标签用
  `样例`、`示例`、`实例`。这与「那一X 与这一X 当名词」同源：量词一进标签，标签就变成了口语。
- **「它自带的」「它自己的」这类所有格是叙述，不是命名。** 标签不必交代这份 rubric
  从哪来、归谁所有，直接叫它 `专家 rubric` 就够了。同族的还有「X 提供的 Y」
  「X 里面的那个 Y」「由 X 给出的 Y」。
- **专有名词第一次出现时，名字在前，中文注解放括号里。** 这与前面「英文进中文句子的
  三条位置规则」不冲突，两条管的是不同的东西：
  - **概念**本来没有名字，所以中文先说它是什么，英文名跟在括号里：
    `训练历史记忆（training-time memory）`。
  - **专有名词**（bench、数据集、模型、机构）本身就是名字，中文注解跟在括号里：
    `HealthBench（医疗问答任务）`、`WebArena（网页导航）`。写成「医疗问答基准
    HealthBench」会让读者以为「医疗问答基准」是一个术语。

**判断方法：把这个标签念出来，它像不像一个词条？** 像句子就重写。

### 内部报告的结构和词都不进对外文档

把一份内部报告的小节名、字段名原样搬进 deck 或对外文档，是最容易发生也最难自查的一类
串味：写的人手上摊着那份报告，读的人没有。作者读到时的原话是「报告的内容不是让你抄的，
像前面的论文一样，逻辑的，用词呢」。

| ✗ 报告里的说法 | ✓ 对外文档 |
|---|---|
| 预研诊断 | 直接说这一页在分析什么 |
| 折算 | judge 按 `criteria` 打分并归一化 |
| 训练样本示例 | 样例 |
| 本消融的 base 行 | 消融的 base |
| 两次不同实验 | 两套独立设置 |

**结构也一样。** 一份对外文档的章节顺序应当和它同类的已发表工作对齐（背景 → 局限 →
根源 → 挑战 → 方法 → 结果），而不是照抄内部报告的「背景 / 预研 / 方案 / 进度」。
判断方法：这个词或这个小节名，在论文、教科书或同行的 talk 里出现过吗？只在自家周报里
出现过，就换掉。

### 「读法」那一栏，删掉而不是改名

表里出现「读法」一列，是在替读者把左边那一列翻译一遍。改名不解决问题，它的内容本来就该
并进右边的动作栏：

```
✗   测到的 |Δ|      读法        第二次调用的动作
    < ε_lo         没起作用     strength 升一级，重发候选

✓   |Δ|            第二次调用的动作
    < ε_lo         没起作用，strength 升一级，重发候选
```

顺带去掉「测到的」。$\Delta$ 本身就是测量结果，前面再加一个「测到的」不增加信息，
与「实测」是同一个毛病：把「跑过」这件事包装成一个技术名词。表头写 `|Δ|` 就够了。

## 样例与引文

### 讲一条样例时，每个指代都要能点回原始记录

样例页是全篇最容易写虚的地方：作者手里摊着完整的 run，写的时候脑子里有画面，
于是「借」「翻过来」「这一档」「另一条题」随手就出来了，读者却只看得见幻灯片上的这几行。

| ✗ | ✓ | 为什么 |
|---|---|---|
| $t\!=\!52$ 只能**借** | $t\!=\!52$ 的 `retrieved+` 只能取自 hindsight 来源 | 「借」既没说借的是哪个字段，也没说从哪个来源取 |
| 它在 $t\!=\!41$ 把这条 criterion **翻**到 0.88 | 把这条 criterion 的得分从 0.12 提到 0.88 | 「翻」是口语，而且吞掉了起点 |
| on-policy **这一档**是空的 | on-policy 来源为空 | 「这一档」要读者回头数，直接叫它的名字 |
| 参考取自**另一条题** | 参考取自 prompt `q7e1c` | 「另一条」在幻灯片上指不到任何东西 |

**判断方法：把这一句单独抽出来给一个没看过这个 run 的人，他能指出你说的是哪条记录吗？**
指不出来，就把标识写上去。

### 说「样例」就给原文，不要给样例的描述

一页写着「样例」「实例」「case」，读者期待的是真实的输入与输出。给一段概括，等于把
样例又抽象了一次，那一页就白花了。作者读到时的原话是「该具体时候不具体，你在干什么」。

| ✗ | ✓ |
|---|---|
| `回答 A：四条 criteria 齐全，措辞简洁` | `回答 A：「不要自行停药，突然停用有血栓风险……」` |
| `取回的原文成了噪音` | `检索得到的 hint 把搜索限制在「game card case」这个窄品类上` |
| `两条都没答好` | `两条都直接给笼统的国际建议，谁都没问地区，都得 0 分` |

原文太长就截断并标明截断（`……（大段机制）`），不要改写成概括。数值、专名、引号里的
原话照抄。**自己编一个例子填进「样例」位是最坏的一种**：它既不具体也不可核对，而真实
的 rollout、真实的 bench 样本通常就在手边。

### 引文先给原文，再给中文翻译

引用的样例（prompt、rollout、criterion、task query）先给原文，翻译跟在后面：短的放在同一行的括号里，长的另起一行。不用译文替换原文，也不把译文单独做成一张对照表。读者要核对的是原文，译文只是帮他读；把译文放在前面或只给译文，等于让他核对一份二手材料。作者为此问过几次「为什么不先显示原始语言，再显示翻译」。

| ✗ | ✓ |
|---|---|
| 只给译文：`2022 年销量第一的商品是什么` | `What is the top-1 best-selling product in 2022.`（2022 年销量第一的商品是什么） |
| 原文一张表、译文另一张表 | 每段原文之后紧跟它的译文 |

**例外：** 为中文听众构造、本来就没有原文的例子，可以只写中文。case 文档的完整要求见「case 文档什么都不省」。

### 「逐字照抄」这类自证不写，把原文摆出来就够了

给一段引文加「逐字照抄」「原样引用」「未作修改」这类标签，是在替读者担心它的真假。
读者本来就默认引号里的是原文；写出来反而显得别处的引文可能被动过手脚。
**把原文摆出来，标签删掉。** 真要说明来源，写它从哪儿来（哪个 run、哪条 rollout），
不要写它有多忠实。

| ✗ | ✓ |
|---|---|
| `两条回答的开头，逐字照抄` | `两条回答的开头` |
| `以下为原文，未作改动` | 删掉整句 |
| `原样搬运的 prompt` | `prompt` |

同族的还有「如实记录」「不加修饰地呈现」。

## 标题

**标题点名主语。** 省掉主语的标题读起来紧凑，但读者要往下读一整段才知道它在说什么。

| ✗ | ✓ |
|---|---|
| `落差有两侧` | `policy 与 rubric 的 gap 有两个方面` |
| `两个读数的推导` | `Δ_g 与 Δ_r 的推导` |
| `被追踪的状态` | `训练状态张量 S 的定义` |

**标题不用疑问句。** 「怎么 X」「X 是什么」「为什么 X」都是把问题当标题，读者拿不到任何结论。一律改成陈述：`可逆是怎么实现的` → `通过加性耦合实现可逆`。

**标题说出断言，或点出内容，它从不解释自己的标题。** 测法：**把冒号前面全删掉，剩下的还带信息吗？** 只是在重述被删掉那半，这标题就是空的。

**「断言还是内容」这个选择，在幻灯片里由 `docs-slides` 定，不由这一节定。** 报告的小标题两种都行，
幻灯片不行：pitch deck 的标题是断言，答辩与技术报告的标题是名词短语，点名这一页的对象和它的哪一面
（`奖励模型的训练目标与偏差来源`、`MethodX 的数据构造：从网页轨迹合成多步任务`）。「工程挑战一」这类序号不进标题，作者把它们从标题里删掉过，留给大纲 bullet。选错的代价
记在 `docs-slides` 里：一份 30 页答辩 deck 的标题全写成了结论句，作者的评价是「全都是瞎写」。
**标题里不出现数字**这一条也在那边，同样只对幻灯片生效。

| | |
|---|---|
| ✗ `挑战：这条线在追什么` | 「这条线在追什么」只是把「挑战」再问一遍 |
| ✓ `开放端训练挑战：反馈的可靠性与训练的动态性` | 点出两个挑战 |
| ✗ `核心挑战：outer reward 怎么定义` | 冒号后面引出的是问题，不是答案 |
| ✓ `outer reward 的定义困难与一条出路` | 说明有困难，且有出路 |

## 作者给定的文字

**作者口述或贴来的中文（「这一页这么写」「解释用这个」「X 改成 Y」）默认照原样放进去：不展开，不补第二句，不顺手润色。** 作者给的是定稿，不是素材；改写之后那句话就不再是他的，他还得重读一遍确认意思没变。他读到一句被展开改写的口述时的原话是「谁让你展开重写的？」。英文交付物的同一条规则在 `writing-style`。

**作者要求润色、改写或挤进版面时，这个要求就是改动的范围；改写交给 `writing-chatgpt`，不由 agent 自己动手。** 作者在「谁让你展开重写的？」后面紧接着说的是「任何重写都要过 our chatgpt polish」。交给 writer 时，把作者的断言、他点名的术语与方法名写成约束（这些断言保留，这些词原样出现），不写「作者的句子不动」：那样写等于取消了他要的润色。先 critique、再修改，然后再 critique、再修改一轮才接受，与 `writing-style` 的同一条规则一致，因为一轮只会留下第一次修改带进来的毛病。writer 回来的稿子里，改了断言、展开了口述或补了解释性填充的那一处退回，换回作者原文。交付时把每一处改动列成「原文 → 改后」给作者。

**作者自己的草稿，要求只是「改一改」时，只改语法**：错字、搭配、标点、半译的术语。断言、顺序与用词选择保持原样，要改断言就先问。

**作者已经认可的长版本，是压缩时的原料，不是改写的起点。** 从长版压出短版时，合并、删减与缩图都可以，原文与例子不重写。作者的要求是用原来长版的材料，「例子不能压缩」。幻灯片的具体做法见 `docs-slides`。

一句口述里的改名同样照办，并按「改名是全局替换」执行到每一处。

## 段末孤行

一段话的最后一行只剩两到四个字（「升效率。」），版面上是用一整行换几个字，在一页纸的简历或一页幻灯片上尤其贵。**先动文字，再动版式。** 文字上有三条路，都不改断言：

- **改写最后一个分句**，让断行落在别处。
- **补几个字本来就该写的内容**（一个对象名、一个限定、一个数字），让末行写满。补的是内容，不是为凑行加的填充词。
- **删不承载断言的词**，常见的四类：

| 类型 | ✗ | ✓ |
|---|---|---|
| 复述上一分句的插入语 | `本文将 X 视为一种训练范式，在这一范式中，数据驱动…` | `本文将 X 视为一种训练范式，数据驱动…` |
| 「整体」 | `本文的整体目标是…` | `本文的目标是…` |
| 「能够」 | `使模型能够自动…` | `使模型自动…` |
| 「进一步」 | `进一步提升效率` | `提升效率` |

三条路改的都是文字。文字是作者给定的，就按「作者给定的文字」走：作者要求了才动，改写与补写交给 `writing-chatgpt`，每处改动列给作者。作者自己给的正是前两条路：最后一行可以改写，也可以多写一点。

实测：同一段文字排在两个版式里，删掉这四类词之后，一个版式少了一行；另一个仍是五行，末行仍只剩两个字，最后靠 `\looseness=-1` 让 TeX 重选断行，同样五行里末行带上了十几个字。**所以验收看编译出来的 PDF：每个版式变体里都没有只剩两到四个字的末行，不看是否少了一行。** 只查一个变体，另一个的孤行会原样交出去。

**改完逐句对照：每个断言（谁、做什么、对象、效果）都还在。** 删掉一个限定语改变了断言的范围（「目前主流」→ 删），就不是删冗词，是改内容，那要作者点头。文字仍解决不了，再动断行位置、字距或栏宽；简历与幻灯片的版式手段（含 `\looseness` 的限度）分别见 `docs-resume` 与 `docs-slides`。

## 一份交给导师的报告里，什么被删了

作者把一份 400 行的稿子删到 180 行交给导师，导师仍然批了。留下的是表、公式、图和图注；删掉的几乎全是我写的句子。逐条对照之后，被删的是同一种东西的几个形状：

| 形状 | 被删的例子 | 该怎么做 |
|---|---|---|
| **表格下面逐行解读的 bullet** | `+ **依赖度**：adaptive 两种策略都把依赖度压到 0.004 以下，JIT 略好于按步` | 表已经说了。表后至多一句，且只写表里没有的条件或前提；一行一条 bullet 是最明显的填充 |
| **「粗体断言：数字复述」** | `+ **OOD 上编辑最高**：0.5285 对组合的 0.5231` | 数字在表里；删掉整条 |
| **表前的引入句** | `evolver 第二次调用读 Δ_g，给出 scheduler 的决定，是一个三路门：` | 表头已经说了；直接放表 |
| **case 后面的「解释」段** | `**解释**  8 条 rollout 在 c1 到 c3 上全部满足，c4 是 5/8：拼接进来的那一半立刻饱和……` | case 只摆 prompt、rubric、rollout、打分结果；读者自己读。见「引了原文不再转述」 |
| **case 的脚手架标签** | `**parent** / **检索得到** / **child** / guidance：无。/ rollout（8 条）` | 一个引文块前只留一个名字或时间戳 |
| **整个「结果」「样例」子节，数是造的** | 为 reweight / composer / specifier 各造一张表，再造一张 $u$ 更新前后的表 | 没跑的数只进主表一次，作者点名要补的那一格才补；导师用一篇真实论文的截图替掉了整节 |
| **标题后面挂一个从句** | `衰减策略：内容与强度两条轴，作用在整组` | 标题是名词短语：`衰减策略：内容与强度两条轴` |
| **说不清操作的动词** | `由目标 criterion 改写而来` | 作者在「改写」上打了括号。写出操作和保留了什么：转成过程要求，不带原文 |
| **说不清条件的形容词** | `满足同类 criterion` | 作者补了「（语义检索）」。检索的键要写出来是什么 |
| **行内公式的写法与文件不一致** | `$\langle$hard rule` | 这份文件的行内公式是 `$ \langle $`，两侧带空格；照文件的写法 |

一句话版本：**给导师的稿子里，作者留下的全是能被核对的东西，删掉的全是替读者读表的东西。**先把表、图、公式、原文摆齐，再决定哪一句非写不可。

## Rules

1. **不用半角 `,` `.` `( )` 充当中文标点；数字、英文原文、代码与公式里的半角符号不在此列。破折号只用成对的「——」**，约每千字一个，每个破折号从句带一个整句别处没有的数字、名字或机制。半角标点是串味的最早信号；没有新信息的破折号从句只是在概括前半句。
2. **中文正文、标题、署名与机构行里，没有夹在两个名称或字段之间的「·」「/」「／」，「不用『·』『/』『／』分隔名称」下的 grep 零命中。** 这几个符号在 CJK 字形旁渲染过大，作者三次指出斜线渲染过大、与文字格格不入。音译人名内部的间隔号（贝尔纳·阿尔诺）是名字的一部分，不是分隔符。
3. **一份文档一种语言。** 中文文档里出现一整段英文，读者要换一次阅读模式。
4. **「少用的词」表下的三条 grep 在交付稿上零命中；每个命中逐条读过再改，不按命中批量删。** 每个 ✗ 词都被作者退回过，按词义写的禁令查不了；一刀切地删单字，会把问题、衡量、推理期这些标准词一起删掉。
5. **「真正」「唯一」「正是」「本身（就）」每节至多留一个，且是承重的那个。** 密度一高，读者把所有断言一起打折。
6. **「不是 X，是 Y」每份文档至多一次**，X 是文档前面印过的数字或断言。为对比而造的 X 没人相信。
7. **标题不用疑问句；疑问词、「那一X」「这一X」跨句时不当名词用，写出那个对象的名字。** 读者得先在心里把它改写成陈述句，或回头去数指的是谁。
8. **不用临时拼出的「动词＋出」（量出、判出、读出、蒸出、跑出），书面中文现成的复合词（提出、给出、指出、输出、抽象出）照用。** 前者是翻译腔，删后者是过度矫正，句子会变硬。
9. **不写源文献没有写过的结论句**（验证了、说明了、体现了、证明了）。图和数已经摆着，结论句是替读者下判断。
10. **摘要、简历、幻灯片页面文字与书面文档用书面语**：口语词与口头讲解的句式换掉，但动词驱动的短句不改成名词堆。讲稿备注按 `docs-slides` 写成念得出的口头句子，只去掉口语词。作者给口语页面的评价是「太白话」；正式不等于名词化。
11. **一句只承一个主要的因果关系，先事实后解释，主语、比较对象与结论都在。** 压进冒号短语的三个概念，读者要自己拆。
12. **没有未定义的 punchline 标签**（探索预算、摊得回来、到顶）。读者无从知道它们指什么。
13. **证据是趋势时不写绝对词；描述前人工作写它缺的机制，不写「只会 X」。** 绝对词一句反例就能驳倒，稻草人被作者两次退回。
14. **并列的兄弟条目同一个句式。** 句式不一读起来像拼贴，作者每次都要求对齐。
15. **一项工作用机制称呼，不直译标题里的比喻。** 直译的比喻不告诉听众方法做了什么。
16. **术语按四问取舍；论文命名过的复合概念整个保留英文，中文修饰语隔一个空格接英文中心词、不加「的」，文档自造的标签面向中文读者时给中文描述。** 半译的名字查不到，也与英文版对不上。
17. **英文只用于名字；名字后的解释与连接分句用中文。** 夹在中文句子里的英文缩写读起来是蹩脚的简写。
18. **概念第一次出现时中文说它是什么、英文名放括号；专有名词名字在前、中文注解放括号。** 两种顺序各自避免一种误读：前者避免翻译腔的同位语，后者避免把注解当成术语。
19. **字段定义写成 `<英文标识符>：中文解释`，一行一个，缩进表层级。** 中文字段名与合并的字段在 prompt 里对不上。
20. **一个对象一个名字，一个符号一个含义。** 写完把反复出现的对象与符号列出来，各留一种写法，再 grep。几种叫法会让读者先确认它们是不是同一个东西。
21. **改名同一遍改完每一页、图、目录、页脚、备注与派生符号，grep 旧写法为零，并报告改了几处。** 只改被指到的那一页，作者就得把同一个词再标一次。
22. **不给已有名字的对象造比喻，也不用比赛与购物的说法写打分与代价；比喻每份文档至多一到两次。** 比喻要先解码，解码出的说法在任何论文里都查不到。
23. **标签、图注、表头、卡片抬头是名词短语。** 这些位置存在的理由就是让人不必读一整句。
24. **样例页给真实的原文，先原文后译文；不写「逐字照抄」类自证，不在引文前后转述原文。** 读者要核对的是原文，概括与自证都替他做了判断。
25. **讲样例时，每个指代都能点回一条原始记录。** 读者手上只有这一页。
26. **作者口述的中文默认照原样放入；作者要求润色、改写或挤版面时，改写走 `writing-chatgpt`，他的断言与点名的术语作为约束交给它，critique 与修改各两轮，每处改动以「原文 → 改后」列给作者；只要求修改的草稿只改语法。** 改写过的口述不再是作者的话，他得重读一遍；作者的原话是「任何重写都要过 our chatgpt polish」。
27. **段末孤行的验收是每个版式变体的编译结果里都没有只剩两到四个字的末行。** 先走三条不改断言的文字路（改写末尾分句、补几个字真实内容、删不承载断言的词），文字是作者的就按第 26 条走，再动版式。同一段字删完冗词，一个版式少了一行，另一个仍要 `\looseness=-1`；只看「少了一行」或只查一个变体，另一个的孤行会原样交出去。
28. **不写文档自述，不写内部稿件编号，内部报告的小节名与字段名不进对外文档。** 读者手上没有那些稿子。
29. **连接词先删，句子真的反转时再加回来；不默认排比三项；「值得注意的是」这类对冲删掉。** drafted 稿的连接词密度是 human 稿的 2.5 倍，读起来是翻译腔。
30. **case 文档什么都不省**：prompt 全文、全部 rollout、全部 criteria 与权重、逐条打分结果、每一步演化前后的原文。只挑最好看的一条，读者无从核对。
31. **一条 bullet 一个 claim，数值挂在子级，一个数的测量条件写在它自己的句子里。** 三组数挤进一条，读者要在心里重排；条件抽到表前，读者要回头找。
32. **来源标注写「跑过」与「没跑，按 X 换算」，不写「实测 / 推演 / 投影」。** 两个技术名词并列，把没跑过的数伪装成另一类结果。
33. **工程动作有英文原名就用英文动词**（`re-grade`、`re-sample`、`checkout`），不硬造中文双字词或比喻。硬造的动词短语读起来是滑稽的画面。
34. **一条禁令不带例外。** 例外会被用来放行大多数实例，「口径」就是这样回来了四次。
35. **所有 ✓ 列跑「少用的词」的三条 grep 零命中，示范句（✓ 列里反引号中的句子与示范大纲）再跑分隔符 grep 零命中；新加一个禁用词或模式时，回头把它跑一遍所有 ✓ 列。** 「看 / 分析」这类候选词之间的斜线是给 agent 看的标记，不是示范句。 ✓ 列带着禁用词，等于在教那个错误；「落点」那一格就是这样被作者退回的。

## Anti-patterns

- **换一个同形词。** 把「量出」改成「读出」，把「推成」改成「推到」。诱人，因为表里列的是词，改的人只查词；禁的是形状，换一个词没有离开这个形状。
- **过度矫正。** 把「冻结」「噪声」「提出」「给出」「推向」这类标准中文也删掉，换成英文或更硬的说法。诱人，因为一张禁词表看上去越严越安全；可这些词作者自己都在写（「从真实场景抽象出本质问题」「给出具体的公式」「主干模型参数始终保持冻结」「对最终问答属于噪声」），删掉它们是把作者的用词改成 agent 的。
- **✓ 列里的禁用词。** 正确示例本身带着另一条规则禁的词（「落点」「判 0 分」「重打分」「hindsight 档」）。诱人，因为示例是在那条规则写成之前录的，新规则加进来时没人回头扫一遍旧示例。
- **半译。** `训练时 harness`、`静态指导`。诱人，因为看上去更像中文；结果是一个查不到、与英文版对不上的词组。
- **Punchline 句。** 每行都是一个像结论的短标签，或一句没有主语的冒号短语。诱人，因为短句读起来有力量；读者拿到的是结论，拿不到理由。
- **稻草人前人工作。** 「现有方法只 X」。诱人，因为它让方法的动机显得更强；一个知道那篇论文的读者读到这句，就不再相信后面的话。
- **替作者润色。** 把一句口述展开成两句，或顺手换了措辞；作者要了润色，却由 agent 自己动手改，不过 writer。诱人，因为改写看起来比照抄更像在帮忙。
- **告诉 writer「作者的句子不动」。** 作者要润色时还这样写，等于把他要的润色取消了。诱人，因为它看上去在保护作者的原文；该交给 writer 的是约束（哪些断言、哪些词必须留），不是禁令。
- **只改被指到的那一页。** 改名、换符号、去掉一个禁用词，只在作者指着的地方改。诱人，因为请求只点了一页；同一个标记下一轮还会回来。
- **为挤孤行改断言。** 删掉「目前主流」这类限定语换来少一行。诱人，因为版面立刻干净了；断言的范围也跟着变了。
- **只看一个版式变体。** 一段字在一个版式里少了一行，就当孤行解决了。诱人，因为改动是同一份文字；另一个变体的断行不同，孤行还在。
- **带例外的禁令。** 给一个禁用词开一个「某种用法可以」的口子。诱人，因为例外看起来更准确；它会被用来放行几乎所有实例。

## Companions
