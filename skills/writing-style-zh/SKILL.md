# Skill: writing-style-zh

## Purpose
用户的中文文档风格规则，`writing-style` 的中文对应版。两者分工干净：**`writing-style` 管英文交付物，这份管中文交付物，互不覆盖。** 一份文档只走其中一份。

## When to Use
写或改一份用户会留存、会发出去的中文文档：周报、报告、设计文档、README、提案。文字本身就是交付物时，这些规则生效。

## Out of scope
1. 会话里的回复，以及聊天中的任何输入输出。
2. commit message、PR 描述等版本控制文本，那些走 `git-commit`。
3. 代码、代码注释，以及用户指定了形状的配置与数据。
4. 日志、终端输出等给机器看的文本。
5. **英文文档**，那些走 `writing-style`。

---

## 标点与格式

1. **中文标点**：`，。、（）——`。正文里出现 `,` `.` `()` 是串味的最早信号，扫一遍改掉。
2. **破折号是成对的「——」，孤立的 `—` 永远不对。** 表格里表示「无此项」也别用 `—`，写「无」或写出实际取值。
3. **「——」的预算约每 1,000 字一个。** 实测：human 版 0.25/1,000，drafted 版 1.78。
   逐句测更准：**破折号从句必须带一个整句别处没有的数字、名字或机制**。drafted 版 61% 的破折号从句一个数字都没有，它们只是在概括前半句。删的是整个从句，不是那两个横杠。

   | | |
   |---|---|
   | ✗ `——不干预，这条轴自己会烂掉` | 前一句的概括 |
   | ✗ `——这就是它只涨 .011 的原因` | 这个数字句子里已经有了 |
   | ✓ `——正好一半` | 一个读者本来得自己算的比例 |

4. **术语的中英取舍见下面「什么时候用英文，什么时候用中文」那一节**，那里有四问的判定顺序。
5. **一份文档一种语言。** 不是每节一种，是整份一种。中文文档里出现一整段英文，就是这条要防的。

## 少用的词

### 一、AI 腔与公文腔

和 `writing-style` 的英文清单一一对应，中文里的常见形态：

| ✗ | ✓ |
|---|---|
| 深入探讨 / 深入剖析 | 看 / 分析 |
| 利用 / 借助 | 用 |
| 赋能 / 助力 | 让…能做什么 / 帮 |
| 展现 / 彰显 / 凸显 | 展示 / 说明 / 指出 |
| 印证了 / 是…的有力证明 | 说明 |
| 无缝 | 顺畅 / 不需要额外步骤 |
| 颠覆性 / 前沿 / 业界领先 | 说清变了什么、新在哪 |
| 拥有 | 有 |
| 为了…而… / 由于…的原因 | 为了 / 因为 |
| 开启…之旅 / 图景 / 日新月异 / 驾驭复杂性 | 写成大白话 |
| 底座 / 基底（比喻义） | 基础 / 那一层 |
| 综合来看 / 总的来说（作收尾开场） | 直接说证据显示什么 |
| 未来 / 接下来（含糊指时间） | 下一步，或写出具体时间 |
| 格局 / 版图（比喻义） | 这一领域 |
| 至关重要 / 关键性 | 关键，或说清它改变了什么 |
| 账本（比喻义） | 记录 / log / 那个文件的名字 |
| 阶梯 / 台阶（比喻义） | 按真正变化的那一维给每一级命名 |
| 抓手 / 闭环 / 打法 / 颗粒度 | 说出实际动作 |
| 旨在 | 为了 |
| 一系列 | 写出具体是哪几个 |
| 极大地 / 显著地（非统计义） | 说清幅度 |

技术词保留原义。`robust`、`significant`、`comprehensive`、`novel`、`scalable` 这些在 ML 写作里带精确断言，该用就用；只在它们退化成空泛褒奖时才避开，**永远不要为了躲一个填充词而丢掉一个正确的技术词**。

### 二、反射式强调

实测：与同期 human 版对照，「唯一」9x、「本身（就）」9x、「正是」5x、「真正」6x。次周的一对上差距已经收平——唯一 3.4 vs 3.5 每万字，正是与真正两边都是 0——所以这一组按维护对待，不当活跃缺陷。

问题从来是密度，不是任何单个实例：「唯一算失败的一类」是一个真的、可核对的唯一性断言，但每三句就自证一次「这才是那个唯一的 X」，读者会把所有的都打折，包括真正承重的那些。**写完一节数一遍这四个词，超过一个还活着的就砍到信息量最大的那个。**

| ✗ | ✓ |
|---|---|
| 真正 | 删掉，或说清具体是什么让这个断言成立 |
| 唯一 / 正是 / 本身（就），当默认强调用 | 只在句子确实是唯一性或同一性断言时留 |

### 三、这个项目不用的词

| ✗ | ✓ |
|---|---|
| 诚实清单 | 本周结论与未决项 / 已有与未有 |
| 我们在哪里 / 这条线在追什么 | 直接说位置，或直接问那个问题 |
| 判读 | 结果 |
| 读法（指「该怎么理解这个结果」） | 直接把结论写出来 |
| 落差 | `gap` |
| 尺子 / 判据 | `rubric`；单条时 `criterion`，复数 `criteria` |
| 拐杖 | `guidance` |
| 形状（指一串状态的走法） | 模式，或 `pattern` |
| 读数 | 直接写那个量的名字，或 测到的值 |
| 门槛 / 抬门槛 | `criterion` 的要求 / 把 `rubric` 写得更严 |
| 通道 | 方案，或直接说 guidance 与 rubric |
| 命中位 | 该 rollout 是否满足该 `criterion` |
| 界（作「上界/取值范围」用） | 取值范围，或 `bound` |
| 取回 / 取来（指从 memory 或索引里拿到内容） | 检索、检索得到。`retrieve` 的中文是检索，不是取回；「随情境一起取回 1 条」→「随情境一起检索得到 1 条」 |
| 回灌（指把结果送回上游） | 返回，或 `feed back` |
| 挡住 / 拦下（指某类失败没有发生） | 说清机制：…都会返回规划，所以这类失败归零 |
| 护栏 | 直接写那条约束 |
| 压下 / 抬高（指某个指标的升降） | 下降 / 上升，并写出是什么引起的 |
| 口径（作「先说 X 的口径」这类开场白） | 删掉开场白；作「统一口径」用时是对的，保留 |
| 实测 | 跑过 |
| 推演 / 投影 | 没跑，按 X 换算 |
| 命中矩阵 | judge 逐条 `criterion` 的判定 |
| 噪声 | 噪音 |
| 冻结 / 冻结的（指参数不更新） | `fixed` |
| 预研诊断 / 折算 / 本消融的 base 行 | 见下面「内部报告的结构和词都不进对外文档」 |
| 逐字照抄 / 原样照抄（作标签或引导语） | 直接把原文摆出来，不必宣告它是原文 |
| 判平局 / 判负 / 判胜（指打分结果） | 打分相同 / 得分更低 / 得分更高 |
| 借 / 外借（指从别处取一条参考） | 取自 / 检索自，并写出取自哪里 |
| 翻过来 / 翻上去（指指标由低变高） | 从 0.12 提到 0.88 / 第一次到 7/8 |
| 这一档 / 那一档（指某个取值或来源） | 点名它：on-policy 档、hindsight 档 |
| 另一条题 / 另一个 / 另一份 | 写出它的标识：prompt `q7e1c`、第二个 checkpoint |

## 句式

1. **否定支点「不是 X，是 Y」，每份文档一次。** 实测在同一内容上 drafted 22 次对 human 1 次，每万字 9.2 对 0.9——这是唯一一条至今没有改善的用词习惯，所以给硬预算。

   X 必须是**这份文档前面印过的数字或断言**，活下来的那一次是在纠正读者刚读到的一个数：「Blind 失败率不是 28.2%，是 0.41%」纠正的是上一张表刚给的数，否定在干实事。其余一律直接说 Y。**不要为了对比造一个没人相信的 X**：「这不是失败，是训练成功之后的必然代价」→「这是训练成功之后的必然代价」，后半句自己就把「不是失败」说清楚了。

2. **反射式三连。** 不要默认排比三项，无论是「形容词、形容词、形容词」还是三条一组的列表。换个分组，或写成一句平常话。

3. **空洞的强调与对冲。** 删掉「值得注意的是」「需要指出的是」「可以看出」「显而易见」「众所周知」「或许」「可以说」，然后把观点直接说出来。

4. **含糊的背书。** 不写「值得关注」「值得探索」，给出它为什么要紧的具体理由。

5. **「从 X 到 Y」的笼统开场。** 写出实际范围。

6. **连接词是同一个毛病换件衣服。** 实测每 1,000 字：human 2.1，drafted 5.2；因为 2 对 11，所以 1 对 9，但 4 对 20。中文靠并置连接相关分句、让关系自己显出来，把「因为…所以…」写在一个读者已经看得见的关系上，读起来就是翻译腔。**先把连接词删掉，句子真的反转时再加回来。**

8. **疑问句形的标题与小标题，一条都不留。** 「怎么 X」「X 是什么」「为什么需要 X」「X 是否真的 Y」写成标题，等于把问题抛给读者再自己回答一遍，读者要读完整页才知道结论。一律改成陈述句：`可逆是怎么实现的` → `通过加性耦合实现可逆`；`为什么需要 JIT` → `JIT 预演的作用`；`rubric 修改是否真的改变区分度？` → `衡量 rubric 修改对区分度的影响`（注意别顺手写成「量出…」，见下一条）。「真的」「究竟」这类口语加强词同时删掉。

9. **不要用「动词＋出／出来」造词，也不要用「…什么」当名词短语。** 这两个形状是同一个毛病：把一个现成的双字技术动词拆成口语式的动补结构，读起来像翻译，而且往往比原词更含糊。**替换时不要顺手换成另一个同形词**——这条是从一次连环返工里记下来的：把疑问式图注「rubric 修改是否真的改变区分度？」改成「量出 rubric 修改对区分度的影响」，改完仍然是被禁的形状，正解是「衡量 rubric 修改对区分度的影响」。

   | ✗ | ✓ |
   |---|---|
   | 量出 X 的影响 | 衡量 X 的影响 |
   | 从对话里读出答案 | 答案取自对话 |
   | judge 判出命中矩阵 | judge 判定命中矩阵 |
   | 从轨迹蒸出 hint | 从轨迹蒸馏 hint |
   | 新域上跑出的轨迹 | 新域上的轨迹 |
   | 上一段写出的 token | 上一段输出的 token |
   | 正文只写出这四个数 | 正文中出现的数只有这四个 |
   | 先出决策 token 再出内容 | 先输出决策 token，再输出内容 |
   | 决定给什么样本、什么 rubric | 决定下一步的样本与 rubric |
   | 调用时生成什么 | 调用时的生成内容 |
   | 只考虑如何编码 | 只优化编码 |

   例外只有一处：**引文里的疑问句照抄**。翻译一句原文是问句的 task query，译文当然还是问句（“What is the top-1 best-selling product in 2022.” →「2022 年销量第一的商品是什么」），这不算违规。

10. **不要自己写结论句。** 「验证了 X」「说明了 X」「体现了 X」「证明了 X」——除非那句结论是**源文献自己写的**并且你能指到出处，否则它就是替读者下判断。图和数已经摆在那里，把事实说完就停。
   | ✗ | ✓ |
   |---|---|
   | `压缩质量与检索质量同步改善，验证了「保留—检索」应联合建模。` | 删掉整句 |
   | `阶段二再提高 4.0 个百分点，说明结果反馈主要学会了生成／放弃的边界。` | `阶段二在四基准均值上再提高 4.0 个百分点。` |
   | `取回错误直接体现在分数上。` | 删掉；上一句已经说了判分方式 |

11. **图已经说过的，正文不再说一遍。** 一页里既有图又有文字时，文字承担图画不出来的那部分：取舍、口径、数字的来源。把方框里的名字用句子重述一遍，读者读了两遍同一件事，还占掉了本该给图的空间。实测一条 bullet 与它上方方框内文字逐字重合，删掉之后那一页才有余量。

12. **口语词不进交付物。** 「东西」「说了算」「什么都没算」「搞定」「弄」这类词在会话里没问题，写进文档就掉档次，而且往往顶掉了一个更准的技术词：「$y=x$ 永远可逆，但什么都没算」→「但没有表示能力」。同一句里把「说了算」用两次这种重复也一并去掉。

13. **不写「不带 X，不带 Y」这类否定清单。** 一句话说清它是什么，读者自然知道它没有什么；列举缺席项是把设计意图写成了辩解。「只引 policy 自己在同一类 criterion 上写过的话，不带数字，不带 criterion 文本」→「policy 的历史输出」。删掉「不带 xxx」，只留那个名词。

14. **引了原文，就不再转述原文。** 原文（prompt、rollout、guidance turn、criterion）摆在引文块里，读者自己会读；在它前后加一句「thinking 把 turn 复述成核对表，正文再抄一遍同一句话」是废话，也是替读者下判断。引文块前只留一个名字或一个时间戳（`rollout（t=66）`），引文块后只写判定结果与数值。

15. **case 文档里什么都不省。** 一个 case 要把 prompt 全文、全部 rollout（八条就八条）、全部 criteria 及其权重、每条 rollout 逐 criterion 的判定、以及每一步演化前后的 guidance / rubric / sample 原文都摆出来。英文原文照抄，每段原文之后紧跟一段中文翻译，用引文块分开。不要「其余类似」「略」「……」，也不要只挑最好看的一条。

15. **「那一X」不能当名词用，点名那个对象。** 「那一段」「那一块」「那一列」「那一行」
   「那一组」「那一份」「那一条」「那一个」这一类，读者必须回头去数才知道指的是谁，而写的人
   当时是看着图或表写的，所以自己不觉得有歧义。**改法不是换一个指示词，是把对象的名字写出来。**

   | ✗ | ✓ |
   |---|---|
   | 该列最高 46.77 | $\lambda_{\mathrm{step}}=2$ 这一列最高 46.77 |
   | 主结果表的 46.66 就取自这一列 | 主结果表报的 46.66 就是 $\lambda_{\mathrm{step}}=2$ 时的准确率 |
   | 取回的条目仍然是写入时的那一份 | 取回的条目仍然是写入时的内容 |
   | 上一页那条 hint | 从成功轨迹蒸馏出的 hint |
   | 这一类占三成三 | Spurious + Inversion 占 33.9% |

   **例外：紧跟在被指对象后面、同一句之内的回指是可以的**，「$\lambda_{\mathrm{step}}=2$ 这一列
   最高 46.77，仍低于 CoT」里的「这一列」有前文紧贴着，不必展开。跨句、跨页、跨图的一律点名。

   同源的一条：**不写文档自述**。「上一页」「下一页」「本页」「如前所述」在幻灯片里尤其糟，
   演讲时页序可能已经变了，读者手上也只有当前这一页。

13. **写取舍时，两侧都点名，因果用动词接起来。** 一句话说「改了 A，B 变好了，C 变差了」时，
   把它压缩成并置的短句，读起来是笔记而不是话。作者改写同一句时补回来的正是这三样：
   **对象的英文名、这个对象是什么、以及「引起了」这个动词**。

   | | |
   |---|---|
   | ✗ | `静态指导让 All-0 下降，但 All-1 高过 base` |
   | ✓ | `静态 guidance 让 All-0 这一 pattern 下降，但在另一个方面，引起了 All-1 这一 pattern 上升的问题` |

   三处差别，每一处都是一条已有规则的实例：`静态指导` 是半翻，改回 `静态 guidance`；
   `All-0` 是个代号，读者需要「这一 pattern」才知道它是一类失效而不是一个数；
   `但…高过 base` 只是并置，`引起了…的问题` 才说出这是前一个动作的代价。
   **判断方法：这句话在说一个 trade-off 吗？是就检查有没有一个表示因果的动词。**
   同一个毛病的其他形态：`压下一类就抬高另一类`、`按下葫芦浮起瓢`、`探索不足又上来`。

14. **工程动作用现成的中文动词，编不出来就用英文。** 这一条与第 9 条同源，但错法相反：
   第 9 条是把双字动词拆成动补结构，这一条是给一个动作硬造一个中文比喻。

   | ✗ | ✓ |
   |---|---|
   | 把报错回灌给规划 | 把报错**返回**规划，或 `feed back` |
   | 两条反馈边把失败挡住 / 拦下 | 这两类失败归零，因为报错与验证结果都会返回规划 |
   | 有一条护栏必须说 | 直接说那条约束是什么 |
   | 对照按机制排成阶梯 | 对照组按机制**逐级增配** |
   | 先说结果的口径 | 删掉，直接说口径是什么 |
   | 训练目标从保真换成 utility | 训练目标**从**保真**转变到** utility |

   「回灌」不是中文用法，「挡住／拦下」把一个统计结果写成了打斗动作，「护栏」「阶梯」是
   给已有名字的东西套比喻（见「别给已经有名字的东西造比喻」）。**「先说 X 的口径」「有两点」
   「我要说清楚」这类交代结构的开场白一句都不要**，标题已经说了这一节写什么。

7. **翻译腔的四个标志**：「基于…的…」堆叠、「进行了…」套在一个已经有的动词上、「其」当所有格、主语和谓语隔了半行。每句读出声，是英文句子换了中文词就重写。

## 这个项目学到的几条规则

### 英文进中文句子的三条位置规则

「英文负责名字，中文负责句子」说的是词该用哪种语言，下面这三条说的是它出现在句子的哪个位置。

**第一次出现：中文说这东西是什么，英文名字放在括号里。** 之后全篇用裸的英文名，不再重复中文解释。

| | |
|---|---|
| ✓ `训练历史记忆，有助于诊断（training-time memory）` | 先说它干什么，再给它的名字 |
| ✓ `更新之前先预演一遍，衡量这次更新的影响（Just-in-time guidance/rubric）` | 同上，括号里是这套机制在论文里的叫法 |
| ✓ `合起来记作 training-time harness 配置（non-parametric）` | 括号里补的是一个英文形容词，中文里没有等价的短说法 |
| ✗ `我们引入 training-time memory，即训练历史记忆，它有助于诊断` | 名字先行，中文成了同位语，读起来是翻译 |

**中文修饰语直接贴英文名词，中间不加空格也不加「的」。** `动态 guidance`、`动态 rubric`、`当前 rollout 结果`、`初始 rubric`。写成「动态的 guidance」会把一个名字拆成一个词组。

**结构性的概念可以自己起中文名，它管辖的内容仍用英文。** `跨步记忆` 这一节里全是 hindsight、foresight、rollout；`跨步检索与跨样本检索` 这一节里全是 scope、last、window + cross_sample。中文名负责在目录里说清这一节讲什么，英文名负责在正文里指准对象。这与「别造比喻」不冲突：`跨步记忆` 命名的是这份文档自己的组织方式，不是给 memory 换个说法。

### 分解关系写成层级要点，不要写成连接句

一段论证如果本身是「这件事分成这几块，每块需要那个东西」，它的形状就是一棵树。把树摊平成句子，读者要自己重新把层级搭回来。

```markdown
+ 方案
    - 动态guidance
    - 动态 rubric
+ 难点
    - 动态更新（演化）的时机：好的诊断（analyzer）
    - 动态更新（演化）的内容：好的更新（updater）
+ 动机
    - 训练历史记忆，有助于诊断（training-time memory）
    - 更新之前先预演一遍，衡量更新带来的影响（Just-in-time guidance/rubric）
```

八行说完「有两个方案、两个难点、两条对应的动机」，而且哪条动机对着哪个难点一眼可见。写成散文要四段，还得靠「其中」「与之对应」这类词把层级找回来。

**判断方法：这段话里有没有「A 分成 B 和 C」「B 需要 D」这样的关系？有就写成缩进。** 散文留给树画不出来的那一步——两条线索在这里合流、或者某个结论与直觉相反。

### 一条 bullet 只承一个 claim，数值挂在子级

一条 bullet 里塞进三组以上数值，读者读到第二组就在心里重排。写法是：**claim 用粗体放父级，每组数值各起一条 `-`**。

| | |
|---|---|
| ✗ | `+ **两个端口都开才三类同降**：全 0 10.5、全 1 13.4、S+I 27.2，Agree 到 48.9；它的全 0 与 RuscaRL 的 10.0 相当，全 1 与 EvoRubric 的 13.2 相当` |
| ✓ | `+ **两个端口都开才三类同降**：`<br/>`    - HarnessRL 全 0 10.5、全 1 13.4、S+I 27.2，Agree 48.9`<br/>`    - AMARIS+G 全 0 10.9、全 1 14.3、S+I 29.3，Agree 45.5` |

### 一个数的基准写在它自己的句子里

一个数的测量条件（在哪个 checkpoint、哪一步、哪个 epoch 测的）跟着那个数走，不要抽出来单写一句挂在表前。抽出去之后，读者看某一条 bullet 时手上没有条件，还得回头找。

| | |
|---|---|
| ✗ | 表前单起一句「各 arm 的占比读在自己的 checkpoint 上」，然后 bullet 里只有裸数 |
| ✓ | `RuscaRL 把全 0 从第一个评测点的 12.3 压到 10.0，读在它 1080 步的 checkpoint 上` |

### 不写文档自述，也不写内部稿件编号

**交代文档结构的句子一句都不要。**「上面四条是分类，这一节把其中一条从头走一遍」「这一节先看已有方法」「留到消融一节再引入」——标题已经说了这一节写什么，这些句子只是把标题再讲一遍。

**内部稿件的日期编号不进正文。**「0812 没有单列」「沿用 0828 的写法」「见 0902 的设计笔记」对读者是空的：他手上没有那些稿子。要引就引 arXiv 号或论文名，其余删掉。

### 标签与图注是名词短语，不是叙述句

卡片抬头、图注、表头、小标签——这些位置只放**名词短语**。写成一句带主谓或带所有格的话，
读者要先把整句读完才知道下面是什么，而这些位置存在的理由恰恰是让人不必读。

| | |
|---|---|
| ✗ | `HealthBench 的一道题与它自带的医生 rubric` |
| ✓ | `HealthBench（医疗问答任务）样例与专家 rubric 示例` |

三处差别，每处都是一条独立的毛病：

1. **口语量词不当标签。**「一道题」「一条回答」「两条计划」是说话时的说法。标签用
   `样例`、`示例`、`实例`。这与「那一X」那条同源：量词一进标签，标签就变成了口语。
2. **「它自带的」「它自己的」这类所有格是叙述，不是命名。** 标签不必交代这份 rubric
   从哪来、归谁所有，直接叫它 `专家 rubric` 就够了。同族的还有「X 提供的 Y」
   「X 里面的那个 Y」「由 X 给出的 Y」。
3. **专有名词第一次出现时，名字在前，中文注解放括号里。** 这与下面「英文进中文句子的
   三条位置规则」不冲突，两条管的是不同的东西：
   - **概念**本来没有名字，所以中文先说它是什么，英文名跟在括号里：
     `训练历史记忆（training-time memory）`。
   - **专有名词**（bench、数据集、模型、机构）本身就是名字，中文注解跟在括号里：
     `HealthBench（医疗问答任务）`、`WebArena（网页导航）`。写成「医疗问答基准
     HealthBench」会让读者以为「医疗问答基准」是一个术语。

**判断方法：把这个标签念出来，它像不像一个词条？** 像句子就重写。

### 内部报告的结构和词都不进对外文档

把一份内部报告的小节名、字段名原样搬进 deck 或对外文档，是最容易发生也最难自查的一类
串味：写的人手上摊着那份报告，读的人没有。作者读到时的原话是「报告的内容不是让你抄的，
像前面的论文一样，逻辑的，用词呢」。

| ✗ 报告里的说法 | ✓ 对外文档 |
|---|---|
| 预研诊断 | 直接说这一页在分析什么 |
| 折算 | judge 按 `criteria` 打分并归一化 |
| 训练样本示例 | 样例 |
| 本消融的 base 行 | 消融的 base |
| 两次不同实验 | 两套独立设置 |

**结构也一样。** 一份对外文档的章节顺序应当和它同类的已发表工作对齐（背景 → 局限 →
根源 → 挑战 → 方法 → 结果），而不是照抄内部报告的「背景 / 预研 / 方案 / 进度」。
判断方法：这个词或这个小节名，在论文、教科书或同行的 talk 里出现过吗？只在自家周报里
出现过，就换掉。

### 讲一条样例时，每个指代都要能点回原始记录

样例页是全篇最容易写虚的地方：作者手里摊着完整的 run，写的时候脑子里有画面，
于是「借」「翻过来」「这一档」「另一条题」随手就出来了，读者却只看得见幻灯片上的这几行。

| ✗ | ✓ | 为什么 |
|---|---|---|
| $t\!=\!52$ 只能**借** | $t\!=\!52$ 的 `retrieved+` 只能取 hindsight 档 | 「借」既没说借的是哪个字段，也没说从哪个档取 |
| 它在 $t\!=\!41$ 把这条 criterion **翻**到 0.88 | 把这条 criterion 的得分从 0.12 提到 0.88 | 「翻」是口语，而且吞掉了起点 |
| on-policy **这一档**是空的 | on-policy 档为空 | 「这一档」要读者回头数，直接叫它的名字 |
| 参考取自**另一条题** | 参考取自 prompt `q7e1c` | 「另一条」在幻灯片上指不到任何东西 |

**判断方法：把这一句单独抽出来给一个没看过这个 run 的人，他能指出你说的是哪条记录吗？**
指不出来，就把标识写上去。

### 「逐字照抄」这类自证不写，把原文摆出来就够了

给一段引文加「逐字照抄」「原样引用」「未作修改」这类标签，是在替读者担心它的真假。
读者本来就默认引号里的是原文；写出来反而显得别处的引文可能被动过手脚。
**把原文摆出来，标签删掉。** 真要说明来源，写它从哪儿来（哪个 run、哪条 rollout），
不要写它有多忠实。

| ✗ | ✓ |
|---|---|
| `两条回答的开头，逐字照抄` | `两条回答的开头` |
| `以下为原文，未作改动` | 删掉整句 |
| `原样搬运的 prompt` | `prompt` |

同族的还有「如实记录」「不加修饰地呈现」。

### 打分结果用分数的说法，不要用比赛的说法

`判平局`、`判负`、`判胜`、`打成平手` 是球赛的词。judge 给出的是分数，
所以说的应该是分数怎么样。比赛词还会悄悄带进一个「两条在争胜负」的框架，
而实际上它们只是各自被独立打了一个分。

| ✗ | ✓ |
|---|---|
| $Q$ 判平局 | $Q$ 打分相同 |
| B 判负 | B 得分更低 |
| 两条打成平手 | 两条得分一样 |

### 说「样例」就给原文，不要给样例的描述

一页写着「样例」「实例」「case」，读者期待的是真实的输入与输出。给一段概括，等于把
样例又抽象了一次，那一页就白花了。作者读到时的原话是「该具体时候不具体，你在干什么」。

| ✗ | ✓ |
|---|---|
| `回答 A：四条 criteria 齐全，措辞简洁` | `回答 A：「不要自行停药，突然停用有血栓风险……」` |
| `取回的原文成了噪音` | `取回的 hint 把搜索锁死在「game card case」这个窄品类上` |
| `两条都没答好` | `两条都直接给笼统的国际建议，谁都没问地区，双双判 0 分` |

原文太长就截断并标明截断（`……（大段机制）`），不要改写成概括。数值、专名、引号里的
原话照抄。**自己编一个例子填进「样例」位是最坏的一种**：它既不具体也不可核对，而真实
的 rollout、真实的 bench 题目通常就在手边。

### 别给已经有名字的东西造比喻

术语保持英文那条挡得住「把 rubric 翻成评分表」，挡不住这种：给一个已经有名字的对象换一个中文比喻，读起来有文采，代价是读者要先解码，而且解码出来的说法在任何论文里都查不到。

**实测：一份 drafted 报告里 落差 6 次、尺子 3 次、拐杖 1 次；同期两份 human-authored 报告里，这三个词各 0 次。**

**比喻的配额是每份文档一到两次，只花在第一次引入一个机制的地方，之后回到那东西本来的名字。** 判断方法：这个比喻是在解释一个读者还没见过的机制，还是只在替一个已有的名词换装？后者删掉。

### 来源标注说发生了什么，别给它起个技术名字

「实测 / 推演 / 投影」把「跑过」和「没跑」包装成两类并列的结果，读者扫过一列只看到两个技术名词，看不出后一类根本没有跑。写 **跑过** 与 **没跑，按 0821 换算**，哪一行是证据、哪一行是算出来的，一眼就分得开。

「投影」还多一层毛病：中文里那是几何与光学的词，拿它指外推是硬造，而「换算」「估的」「外推」都是现成的。

### 什么时候用英文，什么时候用中文

**总原则：英文负责名字，中文负责句子。** 指称某个特定对象、机制或量的名词用英文，把它们连成句子的动词、连词与普通名词用中文。「memory 里存两样东西」「rollout 的输入分布」「$g$ 进 sampler 端」都是对的写法，英文词照常参与中文语法，不加引号也不加书名号。

四问按顺序走，第一个命中的就是答案：

| # | 问 | 命中就 | 例 |
|---|---|---|---|
| 1 | 它是标识符、字段名、专有名词或 bench 名吗 | 英文，原样照抄 | `slot_id`、`split == train`、HealthBench、MedQA |
| 2 | 这个**动作**在英文里有固定说法吗 | 英文动词 | `pull image`、`checkout` 到某个 commit、`mount`、`backward` |
| 3 | 中文里有本领域论文**真的在用**的对应词吗 | 中文 | visit → 访问；response → 回答；hit → 命中 |
| 4 | 以上都不是 | 英文 | rubric、criterion／criteria、guidance、policy、rollout、GRPO、advantage、harness、scope、gap |

**第 3 问卡死在「论文真的在用」，而非「翻得出来」。** rubric 翻成「评分表」翻得出来，但这一行没人这么写；advantage 翻成「优势」会与日常的优势混掉；rollout 翻成「展开」会与数学上的展开混掉。**翻得出来但没人用，或者一翻就歧义，都按第 4 问处理。**

第 2 问单独列出来，是因为**动词短语比名词更容易翻砸，而名词恰恰更容易让人以为已经守住了规则**。名词硬造出来读者还能猜，动词短语硬造出来会直接变成滑稽的画面：

| ✗ 硬翻的动词短语 | ✓ |
|---|---|
| 要拉起钉在指定 commit 的容器 | 要 `pull image`、把仓库 `checkout` 到指定 commit、起容器 |
| 把梯度打回去 | 回传梯度，或 `backward` |
| 把权重灌进去 | 加载权重，或 `load state dict` |

「拉起」「钉」「打回去」「灌」逐个看都是常用动词，凑在一起描述一个工程动作就不再是中文了。

**不要半翻。** 一个词在一份文档里只有一种写法，写完 grep 一遍确认。半翻最常见的形态不是名词，是**中文修饰语配中文中心词**：`静态指导`、`动态判据`、`初始判据`。中心词一旦落回中文，这个词就从一个查得到的名字变成了一个查不到的词组，而且同一份文档里必然会有另一处写成英文。正确形状是中文修饰语直接贴英文名词：`静态 guidance`、`动态 rubric`、`初始 rubric`。

**`criterion` / `criteria` / `rubric` 一律用英文，不译成「判据」。** 这一条是纠正的，不是新增的：这份 skill 从前把 criterion 定为「判据」，而 `docs-weekly` 的 Vocabulary 一节同时把 criterion 列在「不翻译」里，两份互相矛盾了很久。矛盾是静默的，代价是一份 26 页的答辩 deck 全篇写着「判据」。作者读到时的原话是「别尼玛的叫判据了，就叫 rubric，criterion / criteria 直接」。按第 4 问处理：`rubric` 指整套评分标准，`criterion` 指其中一条，`criteria` 是复数。`docs-weekly` 那一侧是对的，以它为准。

**第 4 问的答案不是「造一个中文词」。** 四问走完还是英文时，就用英文；此时去发明「界」「命中位」「阶梯」这类说法，等于把一个能查到的词换成一个查不到的词，那是另一条规则禁止的事。

### 一个对象一个名字，一个符号一个含义

一份长文档里同一个东西被叫成四五种名字，是读者最容易被绊倒的地方，也是最容易积累的一种债。实测一份四十多页的讲稿里，同一个"被生成出来的那段文字"出现过 hint、短提示、提示 m、经验四种叫法；同一个模型出现过记忆策略 $\pi_{\mathrm{mem}}$、独立记忆模型、memory policy、$\pi_\phi$、记忆模型五种叫法。每一种单独看都合理，合在一起读者要先确认它们是不是同一个东西。

**符号比名字更严重。** 同一个字母在不同页表示不同的量，读者会把两页的结论错误地接起来。实测 $q$ 在前十页是"查询"、第十一页起变成论文里的"压缩表示"，而这两页恰好在讨论"$q\to c$ 这个方向没被训练"——读者会直接读错。改法是给其中一个换字母（压缩表示改用 $z$），不是加一句"注意此处 $q$ 含义不同"。

**写完扫一遍**：把每个反复出现的对象和符号列出来，各自只留一种写法，再全文 grep 一次。这件事晚做一天，要改的地方就多一页。

### 指代与量词要跟前文对齐

前一段说「gap 有两个**方面**」，下一句就该是「两个**方案**」。换成「两条**通道**」等于凭空引入第三套词汇，读者要先确认它跟前面是不是同一件事。**改一个名词之前，先 grep 全文看它跟谁配对。**

## 常见的别扭句式

下面这一组来自一次母语审稿：把一份写完的中文报告交给一个只看表达、不看技术内容的中文 judge，让它逐句挑别扭的地方。挑出来的十条集中在六个模式上，都不是用词错误，而是**句子的骨架是英文的**，所以词级的检查抓不到。

| 模式 | ✗ 原句 | ✓ 改写 |
|---|---|---|
| **「那一X」指代一个具体对象**（那一段／那一块／那一列／那一行／那一组／那一份／那一条／那一个） | $\Delta_r$ 是 rubric 变了带来的**那一段** | $\Delta_r$ 是 rubric 变化引起的**那部分分值差** |
| **句尾拖一个「…的事 / …的情况」**，英文 something that would happen 的直译 | 这恰好是 rubric 写得贴合现有回答时**会发生的事** | 这恰恰是 rubric 被写得过于贴合现有回答时的**典型结果** |
| **对话口吻混进报告** | $\Delta_g$ 的走势**要说得保守些**： | **保守地看** $\Delta_g$ 的走势： |
| **主观动词代替客观陈述** | 这与上面**批评前人**的那条…是同一个毛病 | 这与**前文指出的**「部分域缺少对应 bench」是同一个问题 |
| **搭配错误**，词选对了但不与这个宾语搭 | 分成两**族**；边际收益在**收窄**；论证会**绕回自身** | 分成两**类**；边际收益在**递减**；论证会构成**逻辑循环** |
| **半句话**，缺主语或缺谓语 | $\Delta_g$ 只要一遍重打分 | **计算** $\Delta_g$ **仅需**一遍重打分 |

**自查的办法：把每一句单独读出来，问它能不能独立成句、主语是谁、这个动词平时跟这个宾语搭不搭。** 这三问比任何词表都更能抓住翻译腔，因为翻译腔的病灶在结构而不在词。

**一个反向的提醒：动词驱动的句子是对的，不要为了「正式」把它们改成名词堆。** 同一次审稿里被点名夸奖的是「把它拆成两部分」「探索不足这一侧没有对应的手段」这类句子——短、有动词、没有「基于…的…」。正式不等于名词化。

## 标题

**标题点名主语。** 省掉主语的标题读起来紧凑，但读者要往下读一整段才知道它在说什么。

| ✗ | ✓ |
|---|---|
| `落差有两侧` | `policy 与 rubric 的 gap 有两个方面` |
| `两个读数的推导` | `Δ_g 与 Δ_r 的推导` |
| `被追踪的状态` | `训练状态张量 S 的定义` |

**标题不用疑问句。** 「怎么 X」「X 是什么」「为什么 X」都是把问题当标题，读者拿不到任何结论。一律改成陈述：`可逆是怎么实现的` → `通过加性耦合实现可逆`。

**标题说出断言，或点出内容，它从不解释自己的标题。** 测法：**把冒号前面全删掉，剩下的还带信息吗？** 只是在重述被删掉那半，这标题就是空的。

**「断言还是内容」这个选择，在幻灯片里由 `docs-slides` 定，不由这一节定。** 报告的小标题两种都行，
幻灯片不行：pitch deck 的标题是断言，答辩与技术报告的标题是名词短语，点名这一页的对象和它的哪一面
（`参数化记忆的优化目标与不可靠根源`、`R³Mem：工程挑战一，超长文档放不进单次训练窗口`）。选错的代价
记在 `docs-slides` 里：一份 30 页答辩 deck 的标题全写成了结论句，作者的评价是「全都是瞎写」。
**标题里不出现数字**这一条也在那边，同样只对幻灯片生效。

| | |
|---|---|
| ✗ `挑战：这条线在追什么` | 「这条线在追什么」只是把「挑战」再问一遍 |
| ✓ `开放端训练挑战：反馈的可靠性与训练的动态性` | 点出两个挑战 |
| ✗ `核心挑战：outer reward 怎么定义` | 冒号后面引出的是问题，不是答案 |
| ✓ `outer reward 的定义困难与一条出路` | 说明有困难，且有出路 |

---

## 为什么

中文交付物里，用户要的是读起来像连续说话的文字，不是被标点和列表切碎的文字。自造比喻、反射式强调、堆叠的连接词都让段落显得有文采而实际在降低信息密度，也是通用 AI 输出最好认的默认。会话和日志是工作文本，不是交付物，所以刻意不管。

## Companions
`writing-style`（英文对应版，管英文交付物，两份互不覆盖）· `docs-weekly`（分阶段的周报配方，正文用哪种语言就走哪一份 style skill）· `docs-slides`（讲稿与备注，另加一条必须能念出声）· `docs-plan` 与 `docs-arch`（活文档）· `git-commit`（版本控制文本，这些规则刻意不管）。
